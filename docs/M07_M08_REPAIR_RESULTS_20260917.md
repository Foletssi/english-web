## 已修复的问题

| 使用场景 | 原因或风险 | 本地修复 |
| --- | --- | --- |
| 点击永久删除直接报不可用 | 页面未核对服务能力，生产开关及调度未就绪 | 新增管理员能力接口；按钮显示真实可用状态和中文原因，可重新检查 |
| 清理多次失败后无法继续 | NEEDS_ATTENTION 不在自动领取范围，旧的 plan/confirm 又直接返回旧任务 | 独立管理员重试 RPC，保留确认范围、回执及已删数量，重置失效租约和重试预算 |
| 取消删除后按钮失效 | 正常取消未走异常恢复分支 | finally 恢复仍在页面上的按钮 |
| 切到其他页面却被回收站覆盖 | 轮询结果返回时没有验证当前页面 | 路由、会话、页面代次校验；退出登录在等待 signOut 前即使旧轮询失效 |
| 请求超时却显示“删除未开始” | 网络失败不能证明服务端没接受确认 | 改为“暂未确认清理结果”，提示重新检查真实状态 |
| 上传失败后重新打开要从头开始 | 上传窗口重开清除了已上传源文件和幂等键 | 保留待提交队列、已上传信息、视频 ID 和幂等键，响应丢失后复用同一任务 |
| 处理节点检查一直等待 | 健康请求没有时间上限 | 8 秒中止，可再次检查，成功和失败均释放计时器 |
| 旧任务重试或回传覆盖新任务 | 缺少“该视频当前任务”校验，旧教学 v4 入口也可绕过 | 重试、普通结果、教学 v4/v5 都经快照与任务锁校验；旧任务拒绝写入 |
| 重试后恢复预算已经耗尽 | 人工重试没有完整重置自动恢复状态 | 明确增加尝试轮次并恢复自动重试预算；重复提交仍由状态校验拒绝 |
| 删除期间上传成品导致文件重新出现 | 普通对象写入和删除清单扫描存在并发窗口 | 使用可恢复的 R2 multipart 上传回执；删除先终止在途上传，再重新列举文件，按租约清理 |
| 确认删除后新草稿引用待删原片 | 只校验删除时快照，未防后续新引用 | 创建处理任务、保存草稿和发布快照均阻止引用已确认删除的独占源文件；共享文件仍保留 |

## 数据映射与联动

1. 回收站视频从草稿和发布目录移除；学生端依赖公开的发布快照及 revision 刷新，不读取管理端私有表。
2. 处理中心按有效视频分组，已入回收站的视频不再形成可操作处理卡片；数据库任务行保留到永久删除成功再清理。
3. 文件删除范围由服务器产生，包含独占源文件与对应成品前缀。客户端不能传任意对象键要求删除。
4. 确认后不可恢复为草稿。失败续跑复用原确认范围，不扩大范围、不重新创建可恢复的视频。
5. 成品上传回执只有服务端可以写入和完成；不能仅因超时就认定写入已停止。终止失败时保留回执并停止删除，避免文件复活或遗漏。
6. 最终数据库清理沿用已有的处理任务、事件、运行记录、封面和语音关联删除关系。保留最小删除记录及学员既有学习统计。
7. 已打开的学生页面在读取新版快照时更新；本轮没有新增向所有在线页面实时推送删除通知的机制。

1. 恢复允许的 Cloudflare 配置访问，核对生产 R2 绑定、Supabase 服务凭据及清理凭据；不在报告、前端或日志中输出密钥。

3. 通过官方 Supabase CLI 应用上述两份前向迁移并核对；未成功前不得推送 main。
4. 依仓库规则快进 main、推送 GitHub，由连接 Git 的 Cloudflare Pages 发布；通过 HTTPS 核对上线文件和受保护接口。
5. 保持物理删除开关关闭，确认旧版本普通 PUT 上传请求已结束，新的上传回执协议已生效；不得让旧请求与物理删除重叠。
6. 配置匹配的服务端清理凭据、安装并验证持久调度。数据库中的 schedulerReady 仅证明对应 active cron 存在，不证明凭据正确或调用成功；须另外验证请求结果。
7. 确认没有已确认待删任务后，启用开关并验证空队列 worker 为 IDLE。发布验收不允许创建真实删除任务，不允许删除真实媒体。
8. 真正删除只能由管理员在回收站对具体视频确认后启动。若配置访问或验证仍受阻，保持未启用并报告准确原因，不能跳过门禁。

发布恢复：Git 保留原版本，用户其他未提交工作未被清理。若发布后需要恢复，应先关闭删除入口并重新部署使配置生效，保留回执/审计结构，按前向迁移修复；不要直接回退到可能绕过新保护的旧上传代码。
