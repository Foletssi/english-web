### 3.2 引擎比较

| 候选 | 核查来源 | 优点 | 本项目中的限制与判断 |
| --- | --- | --- | --- |
| Kokoro + kokoro-onnx | [Kokoro](https://github.com/hexgrad/kokoro)、[ONNX 实现](https://github.com/thewh1teagle/kokoro-onnx) | 可在后台本地运行；英语美音/英音；不需要另购按字计费 API | 优先验证。模型 Apache-2.0、ONNX 包 MIT；依赖与实际选用语音资源仍需随版本核对。发音质量、CPU 耗时和内存尚未实测 |
| Piper | [OHF-Voice/piper1-gpl](https://github.com/OHF-Voice/piper1-gpl)、其 docs/VOICES.md | 本地运行、CPU 路线、已有应用采用 | 备选。引擎 GPL-3.0，各音色模型许可分别核对；声音质量不能由项目热度推断 |
| edge-tts | [rany2/edge-tts](https://github.com/rany2/edge-tts) | 接入较简单，无需自行运行大模型 | 依赖 Edge 在线服务，不是真正离线引擎；不作为学生端唯一生产发音来源 |
| 浏览器 speechSynthesis | 浏览器内置语音能力 | 可作为可选降级能力 | 设备语音包、声音质量、网络和浏览器行为不同；不能保证每台手机统一发音 |

Kokoro 主模型为 82M 参数；ONNX 项目说明中常规模型约 300MB、量化模型约 80MB。这是模型文件级别，不是完整安装大小或运行内存，更不应让每个学生手机下载模型。

**建议：先验证 Kokoro ONNX，采用后台预生成、云端存储、手机按需播放。** 本地处理电脑只负责新音频生产；已经上传的音频在电脑关闭时仍应能播放。若音质或目标环境不达标，再评估 Piper 或明确报价的托管方案，不静默切到不稳定的免费在线服务。

### 3.3 音频生成与前后台对应关系

```text
已审核字幕及语境释义
  → 程序确定普通词/短语及读音需求
  → 后台生成队列（去重、有限重试、版本绑定）
  → Kokoro 生成 WAV → 转码为手机兼容的短音频
  → 现有对象存储与受控媒体服务
  → 学生点词卡“单词发音”或“短语发音”
```

1. M08 负责生成与任务状态；M07 负责发布已检查资源；M04 负责请求和播放；M06 收藏保留来源。M01 继续提供唯一会员准入结果。
2. 覆盖对象是所有可点击的词卡和已审核短语，而不只是重点列表。普通词有发音不意味着它被升级成高级重点词。
3. 已审核短语整体生成音频，不把单词音频拼成一句。read、live、wind 等多音词必须结合时态和词义选读音；仅用小写单词作为缓存键会串音。
4. 音频标识至少绑定 videoId、contentRevision、sentenceId、tokenId/expressionId、读音修订、voice、modelVersion。可以按已确认的文本和读音特征共用底层文件，但不能跳过各视频的访问检查。
5. 服务端依据合法词卡标识读取已发布文本，不接受任意匿名文本生成请求。缓存键由服务端生成，不含令牌或个人资料。
6. 每个生成项初次失败后最多自动重试两次，任务归入对应视频卡片。依赖故障应显示真实原因与重试状态；不生成数千条管理员手工复核待办。
7. 生成阶段就检查音频可解码、非空、时长合理；抽查单词、短语、多音词、缩写和不同语气的试听效果。新视频发布前核对完整覆盖；旧视频沿版本分批补齐，不能因单项失败把有效旧数据覆盖为空。

以下是官方示例形态的技术验证代码，不是已接入本项目的成品：

```python
import soundfile as sf
from kokoro_onnx import Kokoro

engine = Kokoro("kokoro-v1.0.onnx", "voices-v1.0.bin")
samples, sample_rate = engine.create(
    "figure out", voice="af_sarah", speed=1.0, lang="en-us"
)
sf.write("phrase.wav", samples, sample_rate)
# 生产流程再转码、验证、上传、登记版本；不把本机路径交给学生端。
```

来源：[kokoro-onnx examples/save.py](https://github.com/thewh1teagle/kokoro-onnx/blob/main/examples/save.py)。实施时锁定具体依赖与模型版本，音色以上线试听结论为准。

### 3.4 点击行为与费用

- 词卡保留小型播放图标和清楚的可访问名称，点击区域至少 44×44 CSS px，图标约 18px。按钮状态为就绪、加载、播放、可重试。
- 首次点击可显示轻量加载反馈；快速点其他词、关闭词卡、切视频或退出账号，应停止当前发音并取消过期请求。只能有一个发音源。
- 开始词卡发音前暂停视频并暂停循环调度，不能让单句回跳抢声音。发音结束不擅自恢复视频，由用户继续播放；手机遵守用户手势播放限制，处理 play() 拒绝。
- 保留“原句播放”作为语境模仿入口，与合成发音明确区分。不新增手机音量滑块，使用系统音量。
- 首页不下载语音全集；点击时按需取音频，可有界缓存最近使用的少量资源。媒体缓存继续遵守现有登录、有效期和账号切换规则。
- 自托管路线无需增加新的语音 API 密钥，但需要安装运行环境、模型和音色，消耗生成算力、对象存储和播放流量，不等于零成本。
- 估算公式：`音频字节数 ≈ 码率(bit/s) × 时长(s) ÷ 8`。以单声道 48kbps、平均 2 秒为例，每条约 12KB，1,000 条约 12MB，10,000 条约 120MB，均未计封装和存储开销。短语更长、多音色及多版本会增加用量；最终以实测与账单规则计费，本文不虚报月费。

## 四、视频卡片的彩色标签

### 4.1 正确的数据来源

现有 `shared/catalog-selectors.js` 同时有 topicIds 与 tagIds；`food` 是“美食”分类，`food-culture` 是“饮食文化”标签。它们不是同一个查询字段。前后台已传递这些字段，问题主要是卡片未渲染，不能为此再造一份脱离后台的数据。

本轮统一规则：每张卡片保留独立难度（例如六级），再展示一个主标签和两个副标签。使用已发布、有字幕依据的 tagAssignments/tagIds，第一项为主标签，后两项为副标签；去重并保持后台顺序，不混用 topicIds 来凑数。每个标签保留 `{id, label, tone, role}`。food-culture 在卡片中简写为“美食”。有审核数组时只展示已批准项，待审状态不能被旧 approved 布尔值覆盖；没有审核数组的旧记录兼容已有 tagIds。

已有热门标签继续使用 tagId 筛选。视频卡片内标签仅展示，不增加独立筛选动作，点击仍走卡片的播放入口。控制端与学生端复用相同词典和主次顺序，不能在两个页面分别写“美食”“食物”“饮食生活”。旧数据不足三项时需更新元数据；更新前如实展示，不用默认词假装完整。

| 日常生活 | 蓝 | #E8F1FA / #245985 | #203A52 / #ABD3F4 |
| 美食 | 橙 | #FFF0DF / #81420D | #49321F / #FFD2A0 |
| 旅行出行 | 绿 | #E5F4ED / #23644C | #203E34 / #A6DFC5 |

| 朋友交流 | 玫瑰 | #FAE9EE / #8B3F59 | #472B36 / #F0BDCD |

其他受控标签也必须有固定映射；不能按数组下标或随机数选颜色。正式实现测量文字对比度，目标至少 4.5:1；保留文字与主次语义，不单靠颜色表达意义。

- 位置：视频标题下面，第一行“难度＋主标签”，第二行“副标签＋副标签”，底部保留博主与真实播放进度。即使显示进度，也不能隐藏难度。
- 字体 11px、默认色块约 22px 高、圆角 6px、横向内边距 6px、间隔 4px。主标签字重 650、副标签 500；难度保持中性色。文字放大时允许增长，不固定高度裁字。
- 手机继续使用紧凑双列卡片。标签最多两行，不能把封面、标题和卡片撑成大块信息墙。
- 标签使用非交互 span，不套按钮、不占额外焦点；通过主/副标签的可访问名称说明含义。
- 热门标签按规范 ID 去重，受控同义项再按展示组去重。“日常生活”全局列表只能出现一次；计数来自真实可见已发布视频。

## 五、0.5 倍速的完整实现范围

可选值统一为 `0.5 / 0.75 / 1 / 1.25 / 1.5 / 2`。沿用同一个 speedSelect 和共享状态，手机布局只是移动组件，不单独复制一份速度配置。

```js
// 提议放入 M04 共享播放配置；现有全局模块风格下对外导出。
const PLAYBACK_RATES = Object.freeze([0.5, 0.75, 1, 1.25, 1.5, 2]);
function setVideoRate(video, requested) {
  const value = Number(requested);
  const rate = PLAYBACK_RATES.includes(value) ? value : 1;
  if ('preservesPitch' in video) video.preservesPitch = true;
  video.defaultPlaybackRate = rate;
  video.playbackRate = rate;
  return rate;
}
```

由共享配置生成选项；用户更改、恢复偏好、HLS/native 媒体重新挂载、连续下一条和上一条时都通过同一入口应用。倍速只用于视频；合成单词发音默认正常语速，避免把教学发音错误地降为 0.5 倍。

必须验证：

1. 字幕仍按 video.currentTime 查询，不把时间戳再乘或除倍速；单句边界使用媒体秒。
2. 保持音高能力根据浏览器实际支持使用，不能只写属性就宣称所有设备一致。
3. 连播、逐句练习、单句循环、盲听、听写及暂停后恢复均支持 0.5×。
4. 速度改变时结算上一段学习采样。学习时长按实际有效观看时间计算，不计暂停、缓冲和拖动跨度。10 秒媒体在 0.5× 下连续有效播放约需 20 秒，不能无条件翻倍累计或重复上报。
5. 切视频与恢复播放器后，下拉框、实际 playbackRate、持久化偏好一致；非法值回退 1×。
6. 0.5× 不降低视频分辨率、不减少视频文件总大小，不能把它当作加载速度修复方案。

## 九、汇总结论

本轮不是增加三个孤立按钮，而是把内容生成、后台发布、学生显示与手机交互接成同一套契约：**Kokoro 后台预生成英语发音；首页展示真实、去重、固定配色的标签；视频增加全链路一致的 0.5 倍速。** 同时完成之前的 UI 落地、图片通路、重点与短语下划线、地道中文、全部词卡释义、循环缓冲、连续播放返回和前后台映射修复。

语音恢复不增加播放器高度；普通词可查义、可发音，但不会因此全部成为重点。重点门槛继续面向四级及以上学习者，覆盖不足自动处理，不把日常审核工作甩给用户。实际代码修改与部署应按上述阶段执行并留存验收证据；本文本身不代表这些改动已经上线。
