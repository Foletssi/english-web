日期：2026-09-17。审计范围经用户确认：`bc01818^`（`cf5170345dc73e4e6d2922a5392c8593f10fb909`）至 `b953d725829d90c6ce0459cc8f3b60c45f618af0`（beta6.46.0），聚焦永久删除及直接依赖。

本轮为审计，不启用删除、不调用已认证的删除接口、不实际删除视频、不部署业务变更。仅新增本报告和只读诊断 SQL。此前其他 UI 工作不在本轮重新设计。

## 直接结论

截图报错来自服务端开关，删除尚未进入数据库执行阶段。线上无凭据、无视频 ID 的空请求访问计划入口，返回 HTTP 503、`VIDEO_DELETION_DISABLED`；该请求不具备创建删除计划的身份或参数。代码在鉴权、数据库 RPC 之前判断 `VIDEO_DELETION_ENABLED`，其值必须是 `true`。

这能确认运行环境未通过启用条件，不能区分是变量缺失、值为 false，还是部署环境配置未生效。不是仅凭截图猜测数据库坏了，也没有证据证明这是用户操作错误。

不能仅打开开关即宣称修复完成：生产定时调度缺失，且失败后的人工续跑路径存在确定缺陷。

## Spec

**5 项确定的功能或部署问题**。顺序按删除使用链路展开。

1. **[P1] 线上删除不可用，控制端却呈现可操作按钮。** `functions/api/admin/video-deletions/[[path]].js:118` 拦截请求；`admin/assets/admin.js:199` 未读取服务能力，`:201` 也没有对应中文错误映射。用户要求“确认永久删除后清理数据库和文件”，当前入口完全不能启动。修复应提供管理员可读的删除能力/健康状态，明确告知未就绪原因；依赖验证通过后配置对应生产开关，不应只隐藏错误。

2. **[P1] 持续清理调度未配置。** `supabase/migrations/20260911173000_durable_video_deletion_v1.sql:376` 只定义安装函数，没有自动执行安装。生产 `cron.job` 中对应记录为零。`functions/api/admin/video-deletions/[[path]].js:137` 在确认时仅发起一次后台工作；工作进程每次领取一个任务。任务中断、延迟重试或多任务排队时，仓库没有已验证的持续执行来源。需要配置且验证持久调度，不依赖管理员保持页面打开。不能仅凭缺少该 cron 排除外部另有调度，但本轮没有任何已配置替代调度的证据。

3. **[P1] “继续清理”无法恢复 NEEDS_ATTENTION。** SQL `:69` 对已确认任务直接返回，使 `:72` 的重置分支无法处理实际失败任务；`:234` 再确认仍直接返回；`:261` 领取范围不含 NEEDS_ATTENTION。管理端 `:199`/`:217` 却使用相同 plan→confirm 路径实现“继续清理”。八次失败后任务无法通过该按钮重新执行。应新增管理员重试 RPC，保留原确认时间、服务器对象范围和已删除回执，将可重试任务重新排队并清理失效租约；禁止恢复为可还原草稿。不能靠前端修改状态绕过数据库。

4. **[P2] 取消确认后按钮停留在禁用状态。** `admin/assets/admin.js:241` 先禁用按钮，只在 catch 恢复；`:217` 取消确认正常返回 null。改为明确处理取消结果或 finally 恢复仍有效的按钮，避免用户必须刷新才能重新操作。

5. **[P2] 状态轮询可能覆盖已切换页面。** `admin/assets/admin.js:216` 仅循环开头检查回收站路由，等待和请求结束后直接 renderTrash。期间跳转到其他板块，迟到响应仍可能重绘回收站。需要异步返回后验证路由和页面代次；离开时停止页面轮询。后台任务本身继续由持久调度执行。
