# 后台内容检查与功能整合方案

日期：2026-09-15。状态：代码检查与设计完成，未修改应用、数据库或生产部署。

## 1. 已确认的原因

截图的“3006个问题”不是3006个独立程序故障，也不是3006个视频。它是字段检查结果逐条累加，混合了错误与提醒。

- `shared/content-store.js` 的 `audit()` 遍历视频、句子和重点表达，直接累计 `issues`。一个词卡可以同时产生类型、词头、教学依据等多项问题。
- `shared/learning-contract.js` 的 `sentenceIssues()` 要求表达具备 `expressionType`、`lemma`、`selectionReasonZh` 和布尔型 `needsReview`。截图的三类代码正是这些校验。
- `admin/assets/admin.js` 的 `auditPanel()` 只显示 `severity + code + entityId`。校验器已有中文 `message`，页面却没有使用，也没有提供定位及修复动作。
- `run-audit` 点击处理只执行 `Store.audit()`、提示和重新渲染；没有在此动作中重新拉取云端数据，也没有启动 AI 修复。因此数据不变，重新检查结果就不变。
- `audit()` 对空重点词和空语法说明一律给出提醒，与“简单句允许不选重点表达、无必要语法可留空”的教学要求不一致。
- 视频媒体缺失等条件存在重复检查路径；需要精确去重，而不是删掉真实问题。
- 审计页任务数来自快照 `s.jobs.length`；侧栏按云端任务中的非结束状态视频去重，工作台又使用另一种任务状态过滤。因此数字含义不同，不代表视频复制了几份。云端任务还存在分页，不能拿当前页计算全局总数。
- 内容检查仅检查字段和状态，未实际验证视频网络可达性、会员权限与播放结果。“已发布”不能等同于“实际可播放”。

证据边界：本次未取得完整生产快照逐条重算3006项，不能给出各类问题的精确数量。旧教学数据未补齐新字段与截图高度吻合，但历史成因还需核对云端实际记录及生成版本，不能直接断言某次迁移失败。

已运行隔离示例验证：一个已有中文释义的 `put off` 词卡，缺少上述教学字段时产生截图中的三项错误；补齐有效字段后该句校验为零项。该实验未写入生产数据，不能据此认定线上所有问题都属于这三类。

## 2. 将技术问题变为可操作的问题

| 当前代码 | 面向管理员的说法 | 对应动作 |
|---|---|---|
| EXPRESSION_TYPE_INVALID | 重点表达尚未分类 | 补齐教学资料 / 编辑词卡 |
| EXPRESSION_LEMMA_MISSING | 缺少词语原形或固定表达 | 补齐教学资料 / 编辑词卡 |
| EXPRESSION_TEACHING_FIELDS_MISSING | 教学分析资料不完整 | 补齐教学资料 / 查看具体字段 |
| CORE_MEANING_MISSING / CONTEXT_MEANING_MISSING | 词卡缺少中文解释 | 补齐释义 / 编辑词卡 |
| EXPRESSION_REVIEW_REQUIRED / SENTENCE_REVIEW_REQUIRED | 内容等待确认 | 打开对应句子的审核页 |
| PUBLISHED_MEDIA_MISSING | 视频缺少播放文件地址 | 查看视频文件与处理记录 |
| INVALID_WORD_TIMING | 单词时间与字幕范围不一致 | 打开时间轴检查 |

内容检查本身有必要：它可以在发布前发现词卡残缺、字幕时间错误、关联丢失。但它应提供“发现问题→定位内容→处理→重新检查”的闭环，而不是堆积错误代码。

页面主视图按视频展示：视频封面和标题、受影响句数、待完善词卡数、问题类别及处理状态。展开后显示“第几句、哪个词、缺少什么、如何处理”。错误代码与内部编号收进“技术详情”，保留给排查使用。

顶部统计分别展示：受影响视频、待完善词卡、待确认句子、处理失败视频。底层字段问题总数只放详情；不得把这些不同口径数字相加成一个惊吓式总数。未知词卡归属的历史错误先保留为句子级问题，不伪造词卡数量。

## 3. 代码设计边界

以下为待实现契约及示例，不是已接入代码。沿用现有 JavaScript、内容接口和教学任务，不为整合导航重写后端。

校验输出补齐稳定定位信息；字段路径不是表达身份标识。新增表达标识需要兼容旧数据，旧数据可暂用已验证唯一的规范化 surface 作局部身份。

```js
function makeIssue({videoId, sentenceId = null, expressionKey = null,
  field = '', code, message, severity = 'ERROR'}) {
  return {videoId: String(videoId), sentenceId, expressionKey,
    field, code, message, severity};
}

function deduplicateIssues(issues) {
  const unique = new Map();
  for (const issue of issues) {
    const key = JSON.stringify([issue.videoId, issue.sentenceId,
      issue.expressionKey, issue.field, issue.code]);
    const previous = unique.get(key);
    if (!previous || issue.severity === 'ERROR') unique.set(key, issue);
  }
  return [...unique.values()];
}

const issueLabels = {
  EXPRESSION_TYPE_INVALID: '重点表达尚未分类',
  EXPRESSION_LEMMA_MISSING: '缺少词语原形或固定表达',
  EXPRESSION_TEACHING_FIELDS_MISSING: '教学分析资料不完整'
};

function issueText(issue) {
  return issue.message || issueLabels[issue.code] || '内容需要检查，请查看详情';
}
// 渲染时使用 textContent，或项目现有 escapeHtml；不要直接插入不可信文本。
```

两处校验产生的同类问题必须先统一 videoId、field 等定义，才能准确去重。不同词卡、不同句子的真实错误不得因为 code 相同而合并丢失。视频级分组保留全部子项，只合并展示。

“检查”和“修复”保持不同操作语义：

```text
重新检查：只读拉取最新云端快照与版本 → 对该版本校验 → 展示检查时间与结果
补齐教学资料：创建该视频的文字修复任务 → 展示处理进度 → 返回待确认内容
重新筛选重点表达：调用重新提取模式 → 保留人工锁定项 → 人工确认 → 再检查
处理失败：保留具体原因、阶段和可重试入口；不得显示为修复完成
```

现有 `startLearningRepair(videoId, mode)` 已使用 `Cloud.createLearningRepair(videoId, CloudState.revision, mode)`，可以复用 `fill_missing` 与 `reextract` 两种模式。前者补资料，后者调整不合适的表达选择；缺字段不意味着选词正确，不能一律只补字段。

不要直接复用含初始化写入分支的整体启动逻辑来实现“只读检查”。为检查提供明确的只读刷新路径。刷新失败显示“未取得最新数据”，保留上次结果及时间，不能提示最新检查通过。

后端须保证同一视频同类有效任务不会因重复点击而重复创建，采用事务/唯一约束或现有幂等机制核实后复用；仅禁用前端按钮不足以防重复。写回时校验源内容版本，过期分析结果不得覆盖较新的人工修改。切换页面、刷新或另一管理员操作后，任务状态仍从云端读取。

不能为了消除报警，把缺失类型统一填成 `word`，或把所有词卡标成已审核。修复任务不重新上传或转码，不改视频文件、时间轴、会员权限和学习记录。新结果仍按原有审核流程确认。

对于空重点表达/语法，需显式区分：未分析、分析失败、已分析且无适合内容。只有最后一种允许为空且不提醒。应保存实际分析完成状态和提示词版本，不能通过“数组为空”或补一个当前版本号来推断已分析。

## 4. 后台按五个日常板块整合

| 主入口 | 收纳现有功能 | 重点调整 |
|---|---|---|
| 工作台 | 导入视频、处理中、待审核、失败提醒 | 只展示可点击处理的业务数据，移走英文技术说明和重复审计面板 |
| 视频内容 | 视频库、合集、创作者、回收站 | 列表集中，进入单条视频编辑字幕、重点词、封面和发布状态 |
| 处理中心 | 解析队列、内容检查、审核待办、历史记录 | 复用已有按视频分组队列，整合修复任务和内容问题；技术任务默认折叠 |
| 学员与会员 | 学员管理、会员期限、使用记录、邀请码 | 同一板块的不同页签，保留邀请码复制、续期等现有功能 |
| 系统设置 | AI 配置、处理服务状态、高级维护 | 配置归这里，普通处理失败回处理中心；危险维护保留独立确认 |

现有解析队列已经按视频分组，不需要重新发明一套队列。改的是入口、统计、问题定位和动作连接。

字幕批量审核不可删除，放入处理中心的待审核筛选，并保留原有深链接。原 `/videos`、`/collections`、`/creators`、`/pipeline`、`/subtitles`、`/learners`、`/invites`、`/analytics`、`/settings` 与详情链接继续可访问；导航变化不能破坏旧书签和返回操作。

目前搜索框写“搜索视频、任务或创作者”，实际结果函数仅搜索视频字段。首轮改为准确的“搜索视频”；若确有跨模块搜索需求，再独立实现分类结果，不维持无效承诺。

减少的是重复入口、重复统计和开发文案，不是删除合集、创作者、批量审核、学员记录或问题诊断能力。内容检查也不是全站代码/安全审计，不把一个 PASS 宣称为“全部功能无问题”。

## 5. 分阶段实施与验收

1. **内容检查模块**：保留原校验，补齐中文、视频/句子/词卡定位和准确统计，分组分页；补未知错误的可操作兜底。对照原始结果确保真实错误未丢失。
2. **教学数据模块**：只读取得生产快照，统计具体字段分布及生成版本，区分选词错误与字段缺失；修复走现有文字任务。先单视频验证，确认无人工覆盖与字幕时序变化后再批量处理。
3. **统计与导航**：由服务端给全局按视频聚合的任务统计，明确处理中/失败/待审核/已完成分类；侧栏、工作台、处理中心采用相同口径。分组分页不改变全局总量。再收拢五个入口，保留原路由。
4. **发布验证**：按仓库既定流程，确有数据库迁移先迁移再部署应用；保留旧字段兼容和上一应用版本，失败可恢复应用版本。不得通过删除内容或R2媒体来“清空问题”。

必须覆盖的验收场景：

- 一词缺三个字段：展示一张待完善词卡、三个具体原因；不同词卡不得误去重。
- 本句已完成分析但无合适重点词：不误报；未分析及失败内容仍可追踪。
- 重新检查不调用 AI、不创建任务、不修改数据；云端拉取失败不会显示假通过。
- 补齐与重新筛选为不同动作，重复点击/多管理员操作不重复创建有效任务；版本冲突不覆盖人工编辑。
- 修复完成后仍能看到待确认状态；中文说明可定位原句，失败有可读原因及重试路径。
- 3000条以上诊断采用分组分页，不一次生成数千 DOM 行；筛选和计数依据全量数据或服务端结果，不只依据当前页。
- 导入、自动处理、字幕批量确认、发布、合集/创作者管理、回收站、邀请码复制及会员续期继续可用。
- 学员视频播放、重点词展示及学习记录保持原行为，未以隐藏错误代替修复。
- 生产上线后分别验证后台任务状态、学生端学习内容和真实播放；内容结构检查通过不能代替这些验证。

本方案使用通用工作流技能按“原因证据→模块边界→实施顺序→验证”组织。当前仅交付文档与隔离诊断结果；应用代码、云端数据及线上服务未改动，无需数据回滚。整个后台所有功能尚未逐项实测，不能承诺不存在其他缺陷。
