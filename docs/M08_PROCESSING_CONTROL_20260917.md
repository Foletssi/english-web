## 已确认的故障

## 全流程控制设计（后续范围，不能当作本轮已经完成）

每个视频只保留一张总卡片，展开后按顺序显示：原片保存 → 领取任务 → 视频检查 → 540P 转码 → 字幕识别 → 翻译与重点词 → 发音 → 回传 → 内容校验。发音等实际子步骤应由执行事件驱动，不能用计时器模拟进度。

每一步展示状态、开始时间、最近真实进展和可度量的完成量。上传显示字节数；转码显示已处理时长；AI 显示完成句组数。无法可靠估计时显示“正在处理，耗时…”而不虚构百分比／剩余时间。

| 使用者看到的情况 | 自动处理 | 人工操作 |
| --- | --- | --- |
| 网络短暂中断 | 有限次数退避重试、支持的传输断点续传 | 查看状态；不重复上传 |
| 处理程序退出 | 任务计划程序重启节点，租约到期后恢复 | 检查节点连接 |
| 节点在线但领不到任务 | 记录最近领取成功／失败及可理解的原因 | 重新检查连接；代码故障不能靠刷新假装修复 |
| 节点心跳正常但某步骤无进展 | 分步骤超时判定，先探测再取消该次执行 | 查看原因，受控“重新执行此步骤” |
| 某步骤确定失败 | 保留通过校验的产物与日志 | “继续处理”，跳过仍有效的已完成步骤 |
| 希望中止或排后处理 | 服务端取消标志、终止子进程、撤销当前租约 | “取消处理”；暂停需定义检查点边界，不承诺任意瞬间暂停 |

现有代码已有节点心跳、任务心跳、进度时间、租约恢复、有限自动恢复、错误后“继续处理”、部分检查点缓存和旧任务回写保护。尚缺：完整的领取健康指标、独立取消／暂停入口、统一按步骤恢复操作、原片本地复用通道。刷新页面不是这些功能的替代品。

### 恢复必须遵守的约束

- 操作由服务端确认任务仍是该视频当前任务；按钮禁重复提交，使用幂等请求键。
- 重新执行前撤销旧租约并创建新 run_id，旧进程的进度、产物和提交均不得污染新任务。
- 只有输入摘要、处理配置版本、模型／提示词版本和产物校验匹配的步骤可复用。改了字幕文本后不能复用旧释义或旧发音。
- “重试当前步骤”是服务端认可的恢复边界；不能由前端随意传阶段值来跳过转码、语音或内容验证。
- 断网、忙碌、节点离线、领取错误和任务错误分别显示。心跳在线不代表整条链路健康。
- 连续失败停止自动重试，给出简短原因、建议动作和可复制的诊断编号；原始堆栈留在诊断详情中。

### 本地已有原片如何复用

目前浏览器上传文件到云端，本地 Worker 再按任务下载。浏览器选择过文件并不等于后台 Python 能获得它的真实路径。现有缓存主要复用 Worker 已经下载过的文件，尚不能自动复用首次浏览器上传的原片。

建议新增本机接收通道：用户选片 → 受信任的本地服务保存原片并计算 SHA-256 → 注册任务与源文件摘要 → 本地处理，同时完成云端原片持久化 → 校验云端原片及所有产物后提交。远端节点或本地文件丢失时回退云端下载。先实现可靠本地复用，再考虑上传与处理并行。

不能仅凭文件名或大小认定是同一原片；不能向网页开放任意磁盘路径读取；不能把未保存到云端的任务显示为“已安全上传”。实现后必须覆盖刷新浏览器、关闭网页、电脑休眠、重复提交、云端上传失败和错误文件重选。

## 分阶段验收

第一阶段：修复当前排队故障并观察原任务领取，不重建任务。

第二阶段：补领取健康与步骤级错误说明，统一到现有处理中心，明确可操作状态。

第三阶段：补取消和按有效检查点恢复，测试旧进程回写、双击、租约过期、子进程卡住和重复提交。

第四阶段：本地原片可靠复用，测试摘要不匹配、原片被移动、无本地节点以及云端持久化失败。

本方案无法承诺任何外部服务永不失败；目标是失败可识别、可定位、可恢复，而且不丢原片、不重复创建视频、不覆盖人工修改。
