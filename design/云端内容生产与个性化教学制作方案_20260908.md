# Eastudy 云端内容生产与个性化教学制作方案

日期：2026-09-08。源码审计基线：`366f1e9`（Beta 6.22.0）。

本文是制作方案和现状审计。拟议接口、表、处理器不代表已经上线。本轮没有重置真实账号密码，没有执行生产数据库写入，也没有开通付费服务。

## 1. 结论与建议

建议采用：**Cloudflare Pages 托管网页，Supabase Auth 管登录，Supabase Postgres 管账号和内容数据，R2 管视频文件，本地/独立处理器管 FFmpeg、ASR 和教学分析。**

MVP 可以保留 Supabase 免费版。先做少量真正闭环的课程，再逐步扩展考试内容。页面已上线，不等于后台上传、处理、发布已连到云端。

优先级：

1. 核实 Auth 状态，恢复既有账号登录，做好修改密码与忘记密码。
2. 管理员上传真实视频 → 云端保存 → 真实字幕 → 审核 → 另一台设备上的学生播放。
3. 文案自动标签、词义/短语库、英美发音与逐句练习。
4. 通用学习引擎 + 各考试版本的内容包、题型包和评估规则。
5. 根据跨设备实测、学习反馈、流量成本再扩大内容量。

## 3. 账号为什么存在却登录失败，如何重置

### 3.1 已知事实与待核实项

用户截图可确认两个指定手机号都出现在 Authentication Users 中。用户明确表示使用密码注册，且尚未配置短信。本轮接管 Chrome 用户页时返回 `Debugger unattached`，因此没有取得两个账号的 `has_password`、`phone_confirmed_at`、封禁状态、登录错误日志结果；具体根因仍待核实。

两个手机号使用相同密码不会“冲突”；Supabase 按各自用户 ID 验证密码。常见分支包括：密码输入不一致、Phone confirmation 配置阻止登录、Auth 与 profiles 状态不同步、生产页面指向错误项目、网络/频率限制。不能仅凭红色文案判断是哪一种。

前端将号码规范成 `+86...` 是正确方向。Supabase 控制台可能显示不带 `+` 的 `86...`；展示差异本身不代表数据错误。此前仅用 `phone in ('+86...')` 的 SQL 可能漏查，应使用已确认用户 ID 或规范化号码查询。

只读诊断结果应包括：匹配用户数量、Auth 用户 ID、号码后四位、有无密码（仅布尔值）、Phone confirmation 时间、有无封禁、最近登录时间、profiles 是否存在及角色。不得导出密码散列。实际密码验证结果由 Auth 日志/本人登录返回的错误码确认。

### 3.2 本次账号恢复

1. 明确重置范围，一个还是两个账号；保留原用户 ID，保留学习数据和会员。
2. 在有管理权限的服务端调用官方 `auth.admin.updateUserById(userId, { password: newPassword })`。
3. 新密码通过受保护输入框录入；不要写进聊天、SQL 历史、代码仓库、浏览器日志。
4. 更新成功后核对返回用户 ID；用新密码完成本人登录验证。
5. 单独处理会话撤销；旧 JWT 在到期前是否仍有效要实测，不能承诺点击改密就立即让所有设备失效。
6. 不自动修改手机号归属验证、角色、VIP 或激活状态。若确实是 confirmation 配置问题，按“当前无短信的注册政策”单独修正。

Admin API 密钥仅留在受控服务端/临时管理进程。不要将 service_role 放到学生网页，也不要直接手工改 `auth.users.encrypted_password`。

### 3.3 已登录用户主动修改密码

交互：账户 → 安全设置 → 当前密码、新密码、确认新密码 → 保存 → 成功提示 → 要求重新登录。

当前 Supabase 官方文档支持 `current_password`（supabase-js v2.102.0+）：

```ts
const { data, error } = await supabase.auth.updateUser({
  password: newPassword,
  current_password: currentPassword
});
```

制作时锁定并核验 SDK 版本，不能长期使用未固定的 `@2` CDN。服务器密码策略和前端提示一致；允许粘贴和密码管理器；不对密码做 trim、转小写等隐式修改。建议新账号至少 12 位，旧账号登录继续接受已有合规密码，不因为新注册规则而锁住旧用户。

如 Auth 配置要求 reauthentication nonce，应明确显示补充验证步骤。无短信环境不可把用户引到收不到的验证码流程。对当前已知密码用户可用近期密码验证；对忘记密码用户走下一节。

密码只由 Supabase Auth 存储和校验。profiles 保存昵称、设置等；`has_password` 若保留，只作受信服务端维护的提示缓存，不作为登录凭证。

### 3.4 忘记密码

| 用户状态 | MVP 实施方式 | 后续成熟方式 |
|---|---|---|
| 记得旧密码且能登录 | 当前密码验证后更新 Auth 密码 | 可加近期再验证、多因素验证 |
| 忘记密码，已有已验证邮箱 | 邮件恢复链接 → 设置新密码 | 自定义 SMTP、过期/单次 token、通知和撤销会话 |
| 忘记密码，只有手机号，当前没短信 | “联系管理员恢复账号”，核验身份后服务端重置 | 接真实短信供应商后手机号验证恢复 |
| 未验证手机号却知道该号码 | 仅知道手机号不足以证明归属 | 不开放仅输号码即可改密的接口 |

注册时手机号未验证的账号，后续追加短信恢复还需考虑号码被他人提前注册/运营商回收的情况。绑定验证邮箱或一次性恢复码可以成为补充通道；恢复码与 VIP 激活码完全分开。

OWASP 建议恢复请求统一回复、限制频率、恢复凭证高熵/短期/单次使用、设置密码二次输入。错误恢复 token 不修改账号。人工核验不能只问公开昵称或让对方报手机号。

### 3.5 本项目需修改的具体位置

- `shared/supabase-client.js`：改密参数、Auth 错误分类、可信资料更新、会话事件。
- `assets/js/app.js`：恢复入口按能力开关显示；不再声称短信已发送；注册只在真正成功后显示成功页。
- `index.html`：安全设置补当前密码；配置 `autocomplete=current-password/new-password`。
- Supabase：核验 Phone provider、confirmation、密码策略、Auth 日志、profiles 触发器/RLS。
- 服务端：仅管理员可用的恢复接口、近期身份验证、目标校验、限流和不含密码的审计日志。

## 4. 视频存在哪里，能放多少

额度摘自 2026-09-08 查阅的官方价格页。实际已使用空间本轮未登录核验；下表是套餐额度，不是当前剩余额度。

| 服务 | 放什么 | 免费/计费信息 | 适用判断 |
|---|---|---|---|
| GitHub | 代码、迁移、部署配置 | 不作为用户视频上传目录 | 每发一个视频不应重新提交网站代码 |
| Cloudflare Pages | HTML、CSS、JS、小图片 | 免费站点最多 20,000 文件，单文件 25 MiB | 不作为大视频库 |
| Supabase Postgres Free | 用户、字幕、标签、计划、学习记录 | 500 MB 数据库/项目 | 不把 MP4 二进制塞数据库 |
| Supabase Storage Free | 封面、小音频、少量短视频 | 1 GB 文件容量；单文件最大 50 MB；5 GB 普通 egress 与 5 GB cached egress 按各自规则计算 | 适合非常小的验证库；长 Vlog 很快超限 |
| Cloudflare R2 Standard | 原片、播放 MP4/HLS、字幕文件 | 10 GB-month 免费；每月 100 万 Class A/1,000 万 Class B 操作；直接出口流量免费；超额存储 $0.015/GB-month，操作另计 | 推荐本项目 MVP，需自己转码和维护播放鉴权 |
| Cloudflare Stream | 托管转码与自适应播放 | 存储按每 1,000 分钟 $5 的额度块购买；交付按每 1,000 播放分钟 $1；转码和入站包含 | 更省开发，但属于付费路线，本轮未开通 |

R2 免费额度不是无限量。启用时可能需要账单资料；不要因为“出口免费”而忽略请求量、Workers、转写、AI 及其他服务成本。R2 与 Stream 是两种可选播放方案，不必默认重复购买两套。

### 4.1 以 R2 为例的容量估算

十分钟、平均视频码率 2 Mbps、音频 128 kbps：

```text
播放文件大小 ≈ 600 秒 × (2 + 0.128) Mbps ÷ 8 ≈ 160 MB
10 GB / 160 MB ≈ 62 条十分钟视频（只算单份播放文件）
预留 20% 空间后 ≈ 50 条
```

如果每条还存 400 MB 原片、160 MB 播放版、约 4 MB 封面/字幕/音频片段：

```text
每条合计约 564 MB
8 GB 运营预算 / 564 MB ≈ 14 条
```

因此应该用“原片＋所有清晰度副本＋音频＋封面＋历史版本”的总大小计算。分辨率不是体积的充分条件，时长、码率、编码决定体积。不同编码和文件容器会带来偏差。

Supabase 1 GB 如放平均 40 MB 小视频，理论约 25 条，预留后约 20 条；每条仍需低于 50 MB。观看消耗的网络流量独立于存储容量。

Stream 示例：100 条各 10 分钟的视频占 1,000 分钟存储；若 100 名用户每日观看 20 分钟、持续 30 天，交付约 60,000 分钟。按当前单价估算存储额度 $5 加交付 $60，约 $65，另有税费/其他服务；这不是固定月费报价。

### 4.2 面向中国大陆用户的实际测试

Cloudflare 海外服务和 Supabase 链路在不同地区、运营商的表现不一样。试运行至少用移动/联通/电信与手机网络检查登录、首帧、缓冲和字幕。绑定域名不能直接消除跨境延迟。若后续选择大陆云视频/CDN，再按服务商接入要求确定备案等事项。

## 5. 管理员如何上传，如何保证学生看到

### 5.1 管理端操作流程

管理员单独访问 `/admin/login.html`，通过服务端 admin 权限校验后进入视频库：

1. 点击“上传视频”；选 MP4/MOV 等实际文件，可同时上传 SRT/VTT/文案。
2. 填创作者、版权/来源、标题、可见范围，选择基础分析选项。
3. 系统显示文件大小、实际时长、预计占用空间；管理员确认上传任务。
4. 文件直接上传 R2；进度百分比来自真实上传字节；断网可续传。
5. 处理器产生可播放文件、英文时间轴、中文翻译、重点词语、自动标签。
6. 管理员在“待审核”里校对字幕、词义、切片、标签和练习。
7. 点击“发布”；发布接口校验资源和审核状态，写入发布版本。
8. 另一台设备上的学生重新进入课程列表，读取云端最新发布内容并播放。

普通 YouTube 网页地址不是 `<video src>` 可以直接播放的 MP4。MVP 文件上传和已有合法媒体 URL 分开处理；第三方平台嵌入走对应播放器 API，平台内容复制、配音和下载处理另核对使用权。

### 5.2 建议的服务接口

```text
POST /api/admin/videos                  创建草稿
POST /api/admin/videos/:id/upload       校验 admin，签发限定对象的上传凭证
POST /api/admin/videos/:id/complete     核验文件 HEAD、大小/校验值，进入任务队列
GET  /api/admin/jobs/:id                真实进度、步骤和可读错误
PATCH /api/admin/videos/:id/draft       保存字幕、标签和练习草稿
POST /api/admin/videos/:id/publish      校验并原子发布指定修订版
GET  /api/catalog                      学生可见的已发布内容
GET  /api/videos/:id/lesson             对应版本的字幕、词语、练习
POST /api/videos/:id/playback           校验登录/会员后签发短期播放凭证
```

浏览器不持有 R2/Supabase 管理密钥。上传签名限定对象路径、操作和时效；不要假设普通预签名 PUT 自带可靠的文件大小限制。服务端先做配额预占，上传完成后核验实际大小、格式和校验值，超限文件保持隔离并清理；需要硬性限制时采用经过验证的上传机制。大文件使用 multipart，限制并发和分片，并定期终止过期未完成上传，不经过普通网页函数整包中转。鉴权在每个服务端接口执行，隐藏管理员按钮不等于权限隔离。

建议对象路径：`videos/{video_id}/{revision}/source.ext`、`playback.mp4`、`captions.en.vtt`、`cover.webp`。数据库保存稳定对象 key，不保存几分钟就到期的 signed URL。

私有/会员资源由服务端签发播放权限。仅在页面隐藏播放器而公开 MP4 地址，不能保护 VIP 内容。R2 原始对象可私有；如用 Worker 分发，要正确处理 Range、206、CORS、Content-Type 和短期鉴权。缓存只能共享同一资源内容，不能共享某人的权限判断。

### 5.3 发布一致性

- `videos` 是内容身份；`video_revisions` 是不可变修订；学生读 `published_revision_id`。
- 草稿字幕与已发布字幕分开，编辑中学生继续用完整旧版本。
- 发布事务中检查：媒体 READY，英文时间轴有效，字幕范围不越界，必填字段齐全，人工审核通过，访问范围明确。
- 发布后更新清单版本/ETag，使旧 localStorage 不再覆盖云端；缓存与接口故障应显示重试，而不是退回不相干演示视频。
- 用两台设备、两个账号验收：管理员上传 → 审核 → 学生 A/B 看到同一版本；草稿、下架、无权限内容均不可读。
- 回滚发布指针即可恢复旧版本；暂不删除历史文件。清理旧文件需确认不存在引用且已过回滚保留期。

## 6. 自动处理器必须真的工作

```text
DRAFT → UPLOADING → UPLOADED → PROCESSING → REVIEW_REQUIRED → PUBLISHED
                              ↘ FAILED（保留步骤、可重试）
```

实际步骤：文件探测/校验 → FFmpeg 转码/取音轨 → ASR → 音频对齐 → 标点分句 → 翻译 → 词义/短语识别 → 自动标签 → 练习草稿 → 人工审核。

- 已提供文案：优先校对并与音频对齐；文案不等于时间轴，需识别删改/漏句。
- 未提供文案：ASR 转写后再对齐；WhisperX 有词级时间戳能力，但噪声、重叠说话、专名仍需要复核。
- 不用按字符长度平均分配时间冒充真实词级对齐。
- 没有真实输出文件/字幕，就不能标记 SUCCESS。每步记录输入哈希、版本、耗时、输出位置和错误码。
- `jobs` 支持幂等键、领取租约、心跳、退避重试、失败队列。停止电脑或处理器后显示排队/中断，避免无限假进度。
- FFmpeg/WhisperX 是重任务，放用户本地处理机或独立云任务执行器；Cloudflare/Supabase 边缘函数负责认证、签名、调度等短任务。
- 自动转写与大模型分析按用量单独算成本。开源代码免费不等于 GPU、电费、托管和第三方 API 免费。
- 明确音视频发送给哪个 ASR/LLM 服务；不夹带用户账号数据，密钥只在处理器/服务端。

## 7. 根据文案自动打标签

### 7.1 通用多维标签，不用单一分类承载全部信息

| 维度 | 标签举例 | 生成依据 |
|---|---|---|
| 主题 topic | 日常生活、美食、旅行、职场、教育、文化、健康、自然、科技、观点 | 整段文案与证据句 |
| 场景 scene | 早晨、超市购物、点餐、机场、租房、会议、运动、校园 | 具体对话/事件 |
| 交际功能 function | 叙事、描述、请求、建议、比较、解释原因、表达观点 | 句子功能，可多选 |
| 技能 skill | 主旨听力、细节听力、听写、复述、跟读、写作迁移 | 实际制作的练习 |
| 语言点 language | 短语动词、搭配、连接语、过去叙事、将来计划、弱读/连读 | 文案＋音频证据 |
| 难度 difficulty | 建议 CEFR、语速、句长、罕见词密度、背景知识要求 | 可量化特征＋教师审核 |
| 内容形式 format | Vlog、对话、访谈、演讲、新闻、讲座 | 人工/模型审核 |
| 考试关联 goal | CET-4/6、IELTS 等目标内容包的映射 | 词表、词义、题型和能力证据 |

主题标签每条建议 1 个主标签、最多 3 个副标签；其余维度各自存储。可扩展词表使用稳定 ID、别名和版本，避免“做饭/烹饪/cooking”成为三个重复标签。

口音需音频判断并保留“未知/混合”，不能仅凭英文文案确定英音/美音。CEFR 是推荐估计，不是官方认证结果。

### 7.2 底层流程

1. 将文案按带时间戳的句段切分、去掉空白/音乐标注；保存原始版和修改版。
2. 词形还原、词性、语境词义识别；短语优先匹配，处理词间插入、屈折变化。
3. 从受控标签字典检索候选；模型只能返回字典 ID、证据句 ID 和简短理由。
4. 按固定 JSON Schema 校验；拒绝不存在的标签、越界时间和未在文案出现的证据。
5. 合并句级结果，按主题占比与覆盖度排序。置信分值先作为待校准指标，不把模型自报百分比当精度。
6. 初始阈值如 0.8 仅用于试运行分流；用人工标注集测 precision/recall 后再调整。低置信/冲突全部进复核队列。
7. 教师修改标签优先于模型；每次重新分析产生新建议，不能悄悄覆盖人工决定。

文案可能包含“忽略指令”等句子，处理器只将它作为待分析内容，不执行其中命令或调用工具。

示例输出（设计样例，不是已生成的教学结果）：

```json
{
  "schema_version": 1,
  "video_revision": "revision-id",
  "topics": [{"tag_id":"daily_routine","evidence_sentence_ids":["s2","s3"]}],
  "functions": [{"tag_id":"planning","evidence_sentence_ids":["s2"]}],
  "expressions": [{"surface":"to-do list","lemma":"to-do list","sense_id":"sense-id","sentence_id":"s2"}],
  "difficulty": {"suggested_cefr":"A2","review_required":true},
  "exam_mappings": [],
  "review_status": "pending"
}
```

### 7.3 词表与考试关联

建立共享词义库：`lexemes`（词形）、`senses`（词义）、`expressions`（短语/搭配）、`forms`（屈折变化）、`pronunciations`（音标/口音/资源）、`occurrences`（视频句段证据）。`bank_memberships` 把词义映射到一个或多个目标词表及版本。

同一个词的不同词义分别处理；一个词属于多个目标时复用知识对象，不重复背成多条无关单词。短语有独立释义/语法和语境，不能拆成几个单词的含义相加。

内容包必须记录来源、版本、许可和审核状态。本轮没有证据支持宣称平台拥有“所有考试全部所需词汇”。尤其不要把自行整理的雅思/托福高频词表宣传成官方穷尽词表。

区分三个覆盖率：

1. 目标词表已入库比例。
2. 其中有已审核视频语境/发音/练习的比例。
3. 某学生已通过复测的比例。

某视频出现几个 CET-4 词只代表部分语言材料有关，不等于该视频构成完整四级课程。没出现在 Vlog 的考试词汇需补充经审核的短课、阅读和专项练习，不强行凑标签。

## 8. Vlog 学习重点

核心价值是把语言和真实场景、动作、说话意图联系起来：

- 听出弱读、连读、缩略、省略、语块和停顿，建立“熟词在语流里也听得懂”的能力。
- 学可复用短语、搭配、句型和交际策略，例如计划一天、说明过程、表达偏好。
- 先抓主旨与关键信息，再精听重点，避免逐词点击而忘记整段意思。
- 用复述、替换造句、情景回答把输入变成自己的输出。
- 下次在新视频中再次识别和运用，检验迁移，而非只记原句位置。

建议一条长 Vlog 分成 2–5 分钟的语义片段；每个 20 分钟小课只安排 3–6 个重点表达、1 个主要能力目标。数字是 MVP 起点，要随实际学习负担调整。

20 分钟样例：

| 时长 | 任务 | 验证方式 |
|---:|---|---|
| 3 分钟 | 回忆到期表达 | 隐藏答案，先答后看 |
| 4 分钟 | 无字幕/英文字幕理解片段 | 1 道主旨＋1 道细节 |
| 5 分钟 | 重点语块和声音辨认 | 定位原句、听写/选义 |
| 5 分钟 | 跟读、复述/替换表达 | 回放与可解释反馈 |
| 3 分钟 | 新场景输出和小结 | 1 个情景回答，安排复习 |

Nation 的 Four Strands 提倡课程中意义输入、意义输出、语言形式学习、流利度发展大致均衡。应从一周/整个课程检查平衡，不把每个 20 分钟小课硬切成四等份。Vlog 不能单独替代考试写作、阅读、翻译和限时任务。

发音系统：优先播放原视频对应语块；孤立词/短语使用许可语音资源或 TTS 补缺，显示英/美音。TTS 不等于真人词典录音，设备缺音色时要明确降级。跟读先做录音回听，自动评分另评测，不能把转写相似度直接包装成准确口音分数。

### 9.1 初次入学

### 9.3 计划引擎

输入：目标能力权重、剩余日期、时间预算、各知识点/技能掌握证据、可发布内容、到期复习、兴趣。

输出：今日任务列表、预计耗时、推荐原因、完成标准、遗漏/待制作内容；不能只输出“每天背 20 词”的一句话。

```text
先安排必要到期复习（限制在预算内）
→ 找目标能力缺口与前置知识
→ 挑当前难度可承受、已审核的片段/专项
→ 加入输出任务
→ 总时长不超过预算
→ 当天完成后用实际用时与作答更新明日计划
```

推荐排序可以从解释性规则开始：目标相关性、难度匹配、未掌握知识点覆盖、复习到期程度、兴趣、多样性。各项标准化后组合，权重是产品试验参数，不宣称是别家商业算法。先过滤登录/权益/发布状态，再排序。

跨目标共享相同知识对象：四级和雅思都需要的同一词义只学一次；不同任务表现分别记录。听辨掌握不自动推导写作掌握。更换考试目标保留已有记忆历史，重新计算优先级。

复习使用 `ts-fsrs` 维护 difficulty、stability、due 等状态；每次答题记录时间、等级、耗时、是否看提示及来源。初始可用默认参数，期望保留率 0.9 只是调度目标，绝不承诺每人准确记住 90%。积累足量数据再拟合；预估复习负担太大时减少新学，不用“强制每天加词”制造积压。

```ts
// 设计示例；服务端需验证用户/卡片归属并原子保存 result.card + result.log。
import { fsrs, Rating } from 'ts-fsrs';
const scheduler = fsrs();
const result = scheduler.next(cardFromDatabase, serverTime, Rating.Good);
```

阅读、写作、口语使用各自 rubric 和专项表现，FSRS 仅负责知识项目复习，不代表整套考试能力模型。旧“连续答对两次 mastered”保留为旧状态，迁移后标记待复测，不伪造历史 FSRS 日志。

## 10. 数据库与隔离设计

在现有表上增量迁移，保留已有用户 ID、video_id 和学习记录，不直接重建清库。

```text
auth.users → profiles
videos → video_revisions → segments/sentences/word_timings
       → media_assets → storage provider + object_key
       → processing_jobs + job_steps
taxonomy_terms → content_tags + evidence + provenance
lexemes/senses/expressions → occurrences → reviewed sentence
curriculum_versions → goal_banks → bank_memberships → knowledge_item
learning_goals → learner_skill_state → daily_plans → plan_tasks
user_vocabulary + review_logs + memory_states
membership_entitlements + activation audit
```

- 学生只能读已发布、符合可见性/权益的内容；写自己的进度、词汇、任务作答。
- 管理员经服务端角色校验写草稿、提交任务、发布和账号恢复；学生端不展示管理入口。
- 处理器只领取分配给它的任务，写处理结果；不开放任意账号权限或读取无关学生资料。
- 日志不记录密码、密钥、完整播放签名；转写文案按内容权限管理。
- 发布内容与用户私有学习数据分开；同一内容能共享，用户的错题/计划/录音不串账号。
- 云端是权威源；离线缓存按 user_id + schema_version 分区，有同步版本/冲突处理。
- `settings` 可选择设备级显示偏好；目标/进度/复习记录必须账号级。录音默认本地保存，上传作业才进入对应学生私有路径。

## 11. 实施批次与验收

### A：先恢复可用登录

完成两个指定账号的诊断/指定范围重置；新旧密码验证；不丢用户数据；验证码功能按未配置状态呈现；注册结果不误报；错误日志可定位；普通学生与管理员权限用不同账号验证。

### B：做一条真实云端内容闭环

建立内容表、R2 私有存储、上传签名接口、目录读取接口。先用一条合法视频＋人工 SRT 测试，不依赖 AI。验收必须换设备、换浏览器：管理员发布后学生看到同一视频/时长/字幕，草稿看不到。

### C：接真实处理器

增加媒体校验、转码、ASR/对齐、翻译和人工审核。测试网络中断、超大文件、无声视频、语言识别错误、时间轴异常、重复任务。失败留在 FAILED，重试不重复扣费或重复发布。

### D：标签、词语和发音

建立受控词表，标注一组黄金样本，测自动标签准确性与词义/短语命中；核对英美语音、手机播放失败处理、原句发音、离页暂停。模型候选带证据，教师可覆盖。

### E：学习引擎和目标包

先上线通用/日常路线，并完成一个有足够内容的考试包（建议 CET-4）作为模板；其他目标仍可设置但明确内容建设状态。验收时间预算、不同用户任务差异、已掌握项去重、跨日复习、跨设备一致性，随后复制“模板＋独立大纲/词表/题型”扩展。

### F：稳定发布

数据库迁移先验证，再发兼容接口，最后更新前端；准备内容版本回滚和数据库备份。VIP 表/RPC 的待执行迁移需要完成且单独审计，前端隐藏 VIP 不足以证明会员链路已闭环。

浏览器清缓存后、断网后、退出再登录、切换学生账号后全部回归。监控登录成功率、上传成功率、处理失败率、视频首帧/缓冲、复习完成率和内容空间，而不是只看 HTTP 200。
