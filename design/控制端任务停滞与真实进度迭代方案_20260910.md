## 5. 统一状态：不能再用一个百分比代表所有情况

### 5.1 独立的三类状态

```ts
type JobStatus = 'QUEUED' | 'RUNNING' | 'WAITING' |
  'REVIEW' | 'ERROR' | 'CANCELLED';

type Stage = 'LOCAL_DOWNLOAD' | 'PROBE' | 'TRANSCODE' |
  'ASR' | 'ENRICH' | 'LOCAL_UPLOAD' | 'REVIEW';

type JobActivity = 'QUEUED' | 'NODE_OFFLINE' | 'PROCESSING' |
  'NO_RECENT_PROGRESS' | 'CONTACT_LOST' | 'RECOVERING' |
  'RETRY_WAIT' | 'SYNC_UNKNOWN' | 'REVIEW' | 'ERROR' | 'CANCELLED';
```

- `status`：数据库业务状态，不为方便配色而覆盖。
- `stage`：当前工作阶段，不等于状态。
- `activity`：结合服务端时间、租约、心跳、真实进展、页面同步的新鲜度生成的展示状态。
- “上传原片”的浏览器任务是独立 upload session。创建 processing job 时已不是浏览器上传阶段。
- `REVIEW` 表示自动处理完成、等待人工审核，不等于发布到学生端。

扩展已有管理员任务 DTO，而不是把整个数据库行暴露给客户端：

```ts
interface ProcessingJobView {
  id: string;
  videoId: string;
  status: JobStatus;
  stage: Stage;
  runId: string | null;
  progress: number; // 兼容旧综合进度，不作为精确工时比例
  lastHeartbeatAt: string | null;
  lastProgressAt: string | null;
  metricsReportedAt: string | null;
  leaseUntil: string | null;
  nextRunAt: string | null;
  serverNow: string;
  recoveryCount: number;
  telemetry: {
    substage?: string;
    current?: number;
    total?: number;
    unit?: 'bytes' | 'media_seconds' | 'batches' | 'files';
    rate?: number | null;
    stageEtaSeconds?: number | null;
    etaSampleCount?: number;
  };
  error: {code: string; message: string; retryable?: boolean} | null;
  capabilities: {canRetry: boolean; canCancel: boolean; canPublish: boolean};
}
```

新增字段应由 `admin_list_processing_jobs` 受权返回；不可把 worker token、密钥、完整敏感请求或签名下载地址放入 DTO。

### 5.2 展示推导示例

以下为纯函数，可直接用合成数据单测。`serverNowMs` 使用 RPC serverNow 加上 `performance.now()` 的经过时间；禁止直接依赖用户电脑时钟。

```js
function deriveActivity(job, context) {
  const { serverNowMs, syncFresh, workerOnline, idleLimitMs } = context;
  if (!syncFresh) return 'SYNC_UNKNOWN';
  if (['REVIEW', 'ERROR', 'CANCELLED'].includes(job.status)) return job.status;

  if (job.status === 'QUEUED') {
    return workerOnline ? 'QUEUED' : 'NODE_OFFLINE';
  }
  if (job.status === 'WAITING') return 'RETRY_WAIT';
  if (job.status !== 'RUNNING') return 'SYNC_UNKNOWN';

  const lease = Date.parse(job.leaseUntil || '');
  const heartbeat = Date.parse(job.lastHeartbeatAt || '');
  const progressed = Date.parse(job.lastProgressAt || '');

  if (Number.isFinite(lease) && lease <= serverNowMs) return 'RECOVERING';
  if (!Number.isFinite(heartbeat) || serverNowMs - heartbeat > 90_000) {
    return 'CONTACT_LOST';
  }
  if (!Number.isFinite(progressed) || serverNowMs - progressed > idleLimitMs) {
    return 'NO_RECENT_PROGRESS';
  }
  return 'PROCESSING';
}
```

说明：`NO_RECENT_PROGRESS` 只是“疑似停滞”，不能直接认定死锁、删任务或自动重跑。模型冷启动、长句、慢网可能暂时没有可量化增量。

## 6. 真实完成量、ETA 与停滞判断

### 6.1 各步骤如何测量

| 阶段 | 真实完成量 | ETA 能否预测 |
|---|---|---|
| 浏览器上传 | 已确认分片字节 / 文件字节；当前发送字节另显示 | 有足够吞吐样本后可以 |
| 等待节点 | 排队时间、在线节点、队列位置 | 节点离线不预测；队列位置不能只根据前 50 条计算 |
| 下载原片 | 下载字节 / HEAD 返回总字节 | 可以，需排除重试和版本变更 |
| 素材检查、模型准备 | 开始时间、子进程状态、阶段信息 | 未知就显示准备中，不伪造 55% 后倒计时 |
| 转码 | FFmpeg 输出媒体秒数 / 总媒体秒数，逐档清晰度显示 | 可以，480p 与 720p 分别估算 |
| Whisper | 已识别媒体秒数 / 音轨时长 | 样本足够后显示区间预测 |
| DeepSeek 分析 | 已完成且通过验证的句子批次 / 总批次 | 可以；429 退避时间单独显示 |
| 上传成品 | 已确认字节、文件数 / 总量 | 优先按字节估算，不能把大小不同文件等同工时 |
| 最终提交 | 清单校验、事务提交 | 显示正在校验，不提前报完成 |
| 人工审核 | 已审核句数 / 总句数 | 不预测人工完成时间 |

现有 RemoteProgressStore 已有 EWMA 速率和至少三次样本逻辑，应提取为共用纯函数，补齐下载与成品上传，避免再造第二个计算器。

```js
function estimateStageEta({current, total, rate, samples, stale, activity}) {
  if (activity !== 'PROCESSING' || stale || samples < 3) return null;
  if (![current, total, rate].every(Number.isFinite)) return null;
  if (total <= 0 || current < 0 || rate <= 0 || current > total) return null;
  return Math.max(0, Math.ceil((total - current) / rate));
}

function formatEta(value, stageComplete = false) {
  if (stageComplete) return '本步骤已完成';
  if (value === null || value === undefined || value === '') return '暂无法估算';
  const seconds = Number(value);
  if (!Number.isFinite(seconds) || seconds < 0) return '暂无法估算';
  if (seconds < 1) return '正在收尾';
  return seconds < 60 ? `约 ${Math.ceil(seconds)} 秒` : `约 ${Math.ceil(seconds / 60)} 分钟`;
}
```

ETA 是估计，不是准确承诺。第一版优先保证“本步骤剩余”，有历史样本后再做整条流水线预测；样本少、离线或退避时不编造总 ETA。预测过期必须失效，不能在缓存数字上继续每秒减一。

### 6.2 检测阈值

复用目前 30 秒心跳、240 秒租约，以可配置策略确定：

- 心跳超过 90 秒：显示暂时失联，不立刻回收仍有效的租约。
- 处理节点超过既有健康窗口 150 秒：显示离线。
- 租约过期后增加短暂宽限，再由服务端原子回收。
- 无进展警告按阶段设置。下载/转码、模型准备、Whisper、DeepSeek 的阈值不能相同。
- 不可中断计算的硬期限按视频时长、设备基准和历史耗时配置，不能统一 180 秒强杀所有任务。
- 硬期限触发后先停止对应子进程并记录错误，再按可重试策略恢复。
- `last_heartbeat_at` 只表示持有者报告存活；`last_progress_at` 只有完成量增加或合理阶段变化才更新。前端刷新和重复心跳不算进展。

## 7. 恢复机制：不能只是反复点重试

### 7.1 Worker 必须独立于 Codex

使用既有 Windows 计划任务，不新增收费服务或第三方依赖：

1. 登录/系统唤醒后启动；增加周期性检查机制，避免三次失败后永久不再尝试。
2. 使用进程级单实例锁，计划任务 `IgnoreNew` 只能防止同一任务实例，不能阻止手动启动第二份脚本。
3. 统一固定的 Worker ID、Python 版本、工作目录与模型缓存。
4. 重启时验证 FFmpeg、Whisper 推理、剩余磁盘、必要配置；先报告 STARTING/NOT_READY，不把模型加载期当离线失联。
5. 进程监督与任务处理解耦，任务失败不能把整个领取循环永久停掉。
6. 输出轮转日志：启动、领取、子阶段开始/结束、异常、租约丢失、退出原因；不记录密钥和签名 URL。
7. 明确账号与电源边界：当前交互用户登录任务不保证注销后仍运行；若需要注销后常驻，应单独设计服务账户与凭据配置，不能擅自开启不受限服务。

网页只能查状态和管理云端任务，不能直接启动已关机的个人电脑。若以后要求处理电脑关闭后也继续处理，需要另一个始终在线的计算节点；不是增加一个 API Key 能解决。

### 7.2 租约失效必须停止旧计算

扩展 `ApiError` 为结构化错误，至少保存 HTTP status、业务 code、retryable。不要让所有错误最后只剩一串文字。

```python
def heartbeat_loop(client, lease, stop, cancelled, lease_clock):
    while not stop.wait(30):
        try:
            reply = client.call(
                'worker-job-heartbeat-v2',
                jobId=lease['job']['id'],
                runId=lease['job']['run_id'],
                token=lease['token'],
                request_timeout=10,
            )
            # 按服务端给出的剩余租期更新单调时钟截止时间。
            lease_clock.renew_from_server(reply)
        except ApiError as error:
            if error.code in {
                'JOB_LEASE_LOST_OR_CANCELLED', 'VIDEO_IN_TRASH', 'JOB_NOT_FOUND'
            }:
                cancelled.set()
                return
            if lease_clock.must_stop_before_expiry():
                cancelled.set()
                return
            # 短暂网络故障：记录警告，在有效租约窗口内重试。
```

上例中的 `request_timeout` 是拟扩展的 EdgeClient 参数，不能作为业务 JSON 发送。`lease_clock` 是拟新增的单调时钟适配器：根据服务器时间和请求往返开销保守计算剩余租期。

执行器接到 cancelled 后必须停止它拥有的子进程树。Windows 可使用受控 Job Object；不能按进程名杀掉所有 Python/FFmpeg，更不能结束用户其他转码任务。仅设置 Python Event 不能中断卡在 C/CUDA 调用中的 Whisper，因此需要受监督子进程隔离。

普通遥测不应每秒同步阻塞 FFmpeg 控制循环 90 秒。建议最多每 3–5 秒合并上报最新进度，保留关键阶段事件；续租通道独立。遥测中断可以在有效租约内短暂继续，但租约失效后不能继续上传或提交。

### 7.3 原子回收与有限自动重试

新增 `automatic_recovery_count`、`max_automatic_recoveries`（建议默认 2）、明确下次执行时间和恢复原因。使用既有 run/event 表，不另建第三套任务系统。

下面是受 service_role 限制的事务算法草案，不是可直接贴进生产执行的完整迁移：

```sql
-- 必须封装在固定 search_path、受权限限制的数据库函数中。
-- 与 claim 使用同一锁顺序，并在拿到行锁后重新检查过期条件。
select *
from public.processing_jobs
where status = 'RUNNING'
  and lease_until < clock_timestamp() - interval '30 seconds'
  and cancel_requested_at is null
order by lease_until
for update skip locked
limit 20;

-- 对每条已锁定任务，在同一事务内：
-- 1. 将旧 processing_job_runs 标为 LEASE_LOST。
-- 2. 追加 LEASE_LOST 事件，保留当时 stage 与 error。
-- 3. 清除旧 token、lease 和 run_id，旧执行者从此不能写回。
-- 4. automatic_recovery_count + 1。
-- 5. 未超限且视频未删除：status='WAITING'，设置 next_run_at。
-- 6. 超限：status='ERROR'，error.code='RECOVERY_LIMIT_REACHED'。
-- 7. 不删除原片、已有成品、检查点、学习内容或其他视频。
```

必须同时修改 `processing_claim_local_job`：现有直接重领过期 RUNNING 的路径不得绕过恢复计数。两种实现选其一：领取前复用回收函数，或将同一回收逻辑原子纳入领取函数；不可两者重复计数。

已有 cron `action=run` 当前只返回 `claimed:0`，不能把它描述成有效的常驻处理器。若复用它运行租约看门狗，需要实际调用上述回收函数并验证调度；这个云端看门狗只能修复队列状态，不能替离线电脑转码。

| 情况 | 自动动作 | 管理员看到什么 |
|---|---|---|
| 没有在线节点的 QUEUED | 保留排队，不消耗重试次数 | 等待节点上线 |
| 网络短暂失败/DeepSeek 429 或 5xx | 在预算内退避，优先沿用原阶段 | 第几次尝试、下次时间 |
| 租约过期 | 使旧 run 失效、有限回收 | 正在恢复，已保留完成步骤 |
| 进度暂时不增长但租约有效 | 警告并检查执行器，不盲目并行启动第二份 | 节点在线，暂未产生新结果 |
| 配置缺失/鉴权失败/磁盘不足/源文件损坏 | 停止自动重试 | 错误原因与明确操作建议 |
| 取消或视频进入回收站 | 停旧执行器，禁止重新领取 | 已取消，不自动复活 |
| 连续恢复超限 | ERROR，等待确认处理 | 已暂停自动恢复，错误历史可查 |

### 7.4 真正的断点复用

已有缓存可复用探测结果、完成的 HLS 档位、完整 ASR 结果及 DeepSeek 已验证批次。保留并显示“复用了哪些步骤”。

- 同一 job、同一原片与配置版本且缓存通过校验，才能复用。
- 未完成的临时 HLS 不能当成功档位。
- 目前 ASR 检查点在整段识别完成后保存；中途崩溃会重新做 ASR 阶段，不能宣称支持任意一秒断点。
- 跨电脑没有本机缓存时，必须明确显示将重新计算缺失阶段。首版不为此强加全量云检查点复制。
- 成品重传优先按回执恢复。同一 run 可复用已确认对象；跨 run 必须由服务端验证并建立新 run 的合法引用，不能挪用旧 token 或绕过隔离。
- 自动处理完成以清单验证与数据库提交成功为准。结果提交应支持同一 run 的幂等确认，防止成功响应丢失后被误报失败。
- 前端显示“检查可复用步骤”，不要重试时立刻画出虚假的全流程 0% 或保留旧 99% 冒充新执行进度。

## 8. 上传与入队的可靠衔接

### 8.1 问题

当前 `uploadVideo()` 上传成功以后，浏览器才调用 `admin_create_processing_job()`。两者不可能天然成为一个跨 R2/Postgres 的事务。网络在中间断开时，需要补偿与幂等，而不是重传完整原片。

当前分片成功后才更新进度，每块 8 MB；慢网时会长时间不动。应分别展示“当前发送量”和“服务端已确认量”。达到 100% 字节不代表合并、校验、入队已完成。

### 8.2 拟增加的上传会话

```ts
interface UploadSession {
  id: string;                    // 稳定的幂等身份
  ownerId: string;
  objectKey: string;
  multipartId: string;
  state: 'UPLOADING' | 'VERIFYING' | 'UPLOADED' | 'ENQUEUED' | 'ERROR';
  expectedBytes: number;
  confirmedBytes: number;
  parts: Array<{partNumber: number; etag: string; size: number}>;
  sourceVersion: string | null;   // 采用现有对象版本/回执协议
  jobId: string | null;
}
```

上传会话保存在受权云端表；浏览器可以保存会话 ID，不能把 token/服务端密钥写入本地公开数据。刷新后续传仍可能需要用户重新选择原文件，浏览器不能无权限重新读取本地文件。

最终提交伪代码：

```js
async function finalizeAndEnqueue(sessionId, videoInput) {
  const session = await getOwnedUploadSession(sessionId);

  if (session.state === 'ENQUEUED') {
    return getOwnedJob(session.jobId);
  }

  if (session.state !== 'UPLOADED') {
    await completeMultipartIdempotently(session);
    await verifyObjectAgainstReceipt(session);
    await markSessionUploaded(session.id);
  }

  // 最后一次受权数据库事务中绑定 session、video、job。
  // 同一 session 重发返回同一个 job，不重复创建。
  return createJobFromUploadSession(session.id, videoInput);
}
```

这些函数为拟新增服务端接口职责，不是现有函数。`completeMultipartIdempotently` 必须处理 R2 合并已经成功但响应丢失的情况：通过 object HEAD 与记录回执确认，而不是无条件再次 complete。

先修复现有 RPC 的幂等顺序：同一用户/幂等键已有任务时，验证其上传会话和输入一致后返回已创建任务；仅创建新任务才要求 expectedRevision 匹配。不同输入重复使用同一键返回冲突。

失败分片可以按有限退避重试同一编号；已完成原片不应因为创建任务失败而被 abort/删除。只有明确取消未完成上传或按确认后的清理策略才结束会话；本轮不设计自动物理删除 R2。

### 9.2 请求不会永久 pending

```js
async function withRequestTimeout(work, timeoutMs = 12_000) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeoutMs);
  try {
    return await work(controller.signal);
  } finally {
    clearTimeout(timer);
  }
}

// 示例：Supabase 查询链需在当前 SDK 验证 abortSignal 支持。
const result = await withRequestTimeout(signal =>
  api.rpc('admin_list_processing_jobs', {p_limit: 50}).abortSignal(signal)
);
```

不要只用 Promise.race 放弃等待，却让底层请求不断堆积。活跃任务保留约五秒查询，失败指数退避至三十秒，页面回到前台立即同步；同时保留成功响应时间。超时不清空任务列表，显示“显示的是上次同步结果”。

const hasTaskPanel = path =>

## 10. 控制端其他模块的必要关联修正

1. **登录**：资料请求错误不等于无权限；所有异步提交用 try/catch/finally 恢复按钮。共享上一份登录恢复设计，避免再产生第三套状态。

3. **字幕审核**：后台状态刷新不覆盖未保存编辑；批量确认前验证句子、词级时间轴与表达；已有验证继续保留。

5. **创作者/合集**：受 revision 保护，失败不提示成功；未成功同步的本地变更要保留草稿标记或安全回滚，不能悄悄变成云端事实。
6. **删除/回收站**：取消任务与删除视频是不同动作；恢复为草稿不自动重跑或发布。继续保留逻辑删除、不物理删除原片的约束。
7. **审计/学习数据**：内容质量审计 PASS 不证明任务节点在线；分别显示内容审计、运行健康、云端学习统计，后者没接通就明确标记，不能展示演示数据当真实用户数据。
8. **系统设置**：显示“配置存在 / 节点在线 / 模型已加载 / 最近调用成功”，不把环境变量存在叫“API 已连接”。
9. **安全展示**：上传文件名、标题、简介、字幕默认按文本渲染；链接使用允许的 URL 协议及媒体路径规则。此为静态风险整改，不是本轮已证实生产利用。
