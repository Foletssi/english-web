## 0. 先给结论

1. 注册账号、学生权限、VIP 权益是三件事：Supabase Auth 管登录；profiles 管个人资料及角色；独立权益表管 VIP。注册成功不等于自动成为 VIP。
2. 首页昵称被截断是布局问题，不应通过截短数据库昵称解决。
3. 当前 VIP 是演示逻辑：默认赠送 120 天、前端内置兑换码、到期后又回填时间。必须由服务端真实兑换替换。
4. 退出播放页只是隐藏页面，没有结束媒体会话；视频、TTS、录音回放应有共同的停止入口，旧异步回调也要失效。
5. 不只做雅思和托福。建设可扩展的目标目录，支持升学、大学考试、留学、职业与生活场景。**体系全面考虑，不等于第一版把所有课程假装做完。**
6. 词汇必须按“词义＋短语搭配＋语境＋听辨和输出”建模。收藏过、视频里见过、答对一次，都不等于掌握。
7. 发音是基础能力：许可音频优先，TTS 补缺，视频原句提供真实语境；跟读回放先上线，自动评分单独评估。

## 1. 账号查询与登录：已知、待核实与判断方法

### 1.1 当前核验状态

- 已在用户的 **Chrome** 中访问目标 Supabase 项目，并看到 `profiles`、`user_progress`、`saved_words`、`saved_sentences`、`daily_learning_stats`、`study_events`、`user_vocabulary` 等表入口。
- **尚未取得针对用户本人注册账号的 SQL 查询结果，因此本稿不宣称已确认该账号存在。** 截图昵称或 Supabase 控制台用户名都不等于应用账号记录。
- 先前版本记录中的测试账号不代表用户本人。本次不创建新账号、不重置密码、不清理账号。
- 本地已兼容学生角色 `learner` / `student`；前序部署中发现旧代码只接受 `student`。这能解释一种登录失败，但不能据此断言当前所有失败都来自同一原因。

### 1.2 应使用的最小只读核验

在已登录的 Supabase SQL Editor 中先执行结构查询，再执行限定目标的查询；无需导出全库，也无需查看密码散列。

```sql
-- 先核实字段，避免把本地迁移当成线上真实结构。
select column_name, data_type, is_nullable
from information_schema.columns
where table_schema = 'public' and table_name = 'profiles'
order by ordinal_position;

-- 确认字段后，按用户截图中的昵称筛选；结果仅用于候选匹配。
-- :nickname 是参数占位，不应原样粘贴进 SQL Editor。
select p.nickname, p.role,
       right(p.phone, 4) as phone_last4,
       (a.id is not null) as auth_account_exists,
       a.created_at,
       a.last_sign_in_at,
       (a.phone_confirmed_at is not null) as phone_verified
from public.profiles p
left join auth.users a on a.id = p.id
where lower(p.nickname) = lower(:nickname);
```

昵称可能重复，需要手机号后四位等进一步确认。若资料表无记录，还要在 Auth 用户界面按用户提供的手机号精确查询，区分“Auth 已创建但资料触发器失败”和“注册根本未成功”。不要使用公开的手机号枚举 API。

### 1.3 正确登录链路

```text
注册提交 → Supabase Auth 创建用户 → 数据库触发器创建普通学生资料
        → 校验实际返回值/确认要求 → 明确显示成功、待确认或失败

登录提交 → signInWithPassword 验证凭据
        → 读取本人 profiles → 校验学生角色 → 显示学习页
        → 读取本人权益 → 显示普通/VIP → 加载本人学习数据
```

- 密码由 Supabase Auth 管理，业务表不保存明文、可逆加密密码或密码副本；前端不查询“数据库密码”做比较。
- “账号密码错误”用于真实凭据错误；断网、服务超时、账号资料读取失败分别提示，不要全误报未注册。
- 管理员身份不得改写成“未注册”后允许重复注册；学生端给通用错误，不显示后台入口；管理端服务端仍验证角色。
- 手机号统一规范成 E.164；兼容旧数据前先检查 `+`、国家区号、唯一索引及重复记录，避免建第二个账号。
- 无短信验证的手机号密码注册不能证明手机号所有权。OTP 路线需要真正的短信供应商，Supabase 免费套餐不等于短信免费；未配置时应隐藏或明确标记不可用，不能发送假验证码。
- 本地 `20260907_otp_and_password_status.sql` 的状态标记 RPC 不能不经审计就上线：现有实现允许已登录调用者直接标记 `phone_verified_at` / `has_password`。应从可信 Auth 事件或受限后端读取实际状态，用户请求不是认证证据。
- profiles 的 `has_password` 只作提示，不作登录授权；密码登录是否成功始终由 Auth 判定。
- 新账号普通学生默认可学习免费内容；不把 `is_active`、手机号验证、密码设置、VIP 混成同一个状态。
- 页面不保存密码。若保留“记住密码”文案，应说明实现实际是保存登录会话；推荐文案“保持登录”，在本机独立存储会话。不同学生账号的缓存按用户 ID 隔离；登出清理本账号敏感缓存。

## 3. VIP：只有你发放的有效激活码才能开通

### 3.1 当前问题不是显示错误，而是权益来源错误

`assets/js/app.js:240` 的 `syncVipBadge()` 使用 `now + 120天` 作为兜底；内置 30/90/365 天码；刷新重新算到期时间；到期重新兜底。约 262 行的兑换入口保存本地字符串后就提示更新成功。用户截图中的“Pro 学习者／剩余119天”并不能证明真实会员。

应删除这些授权效果，旧 `vip:cdk` / `vip:expires` 只属于废弃演示数据，**不迁移成真实权益**。已有真实付费用户若存在，必须先核对凭证，不能批量覆盖权益。

### 3.2 产品规则

| 情况 | 展示与权限 |
|---|---|
| 注册成功，未兑换 | 普通学员，免费内容；“输入激活码” |
| 有效码首次兑换 | 开通对应产品和时长，展示服务端到期时间 |
| 同一账号重试同一码 | 返回原兑换结果，不再次延长 |
| 他人已用、码过期、撤销、错误 | 明确失败，不改变现有权益 |
| 已有会员兑换新码 | 从 `max(服务端当前时间, 原到期时间)` 顺延 |
| 权益查询失败 | 显示“会员状态读取失败，重试”；不回填会员 |
| 会员到期 | 普通学员，历史学习记录保留 |

码本身过期与会员权益到期是两个字段。撤销未使用码不影响已兑换会员；若要撤销已发放权益，必须单独操作、注明原因、保留审计，不能连带误删。

### 3.3 表结构草案

以下是逻辑字段，迁移前需核对线上 schema、角色判断函数和权限。

| 表 | 关键字段 | 写权限 |
|---|---|---|
| `activation_batches` | id、产品、默认天数、备注、created_by、created_at | 管理员后端 |
| `activation_codes`（私有 schema） | id、唯一 code_hash、batch_id、duration_days、redeem_before、revoked_at、created_by | 管理员后端 |
| `code_redemptions`（私有） | id、code_id **唯一**、user_id、redeemed_at、granted_until | 兑换事务 |
| `membership_entitlements` | user_id＋product_id **复合主键**、expires_at、revoked_at、updated_at | 兑换事务/受限管理操作 |
| `membership_audit`（私有） | actor、action、target、request_id、前后状态、时间 | 受限后端追加 |

- 只生成高熵随机码，例如 128 bit 随机值再编码成便于输入的分组字符串；非顺序码、非手机号衍生码。
- 规范化规则固定：去首尾空白、去约定分隔符、统一大小写，哈希前后端保持一致。
- 码只存 SHA-256 哈希；高熵是防离线枚举的前提。若用 HMAC，密钥只放服务器，另外设计密钥轮换。
- 原码只在生成时展示/下载一次；管理表中不存可随意浏览的明文码。不要把生成文件提交到 GitHub。
- 默认单次码；“多人码”以后单独设计配额与计数锁，不混用当前规则。

### 3.4 权限与事务

推荐 MVP：Supabase Edge Function 验证用户 JWT、限流，调用**仅后端可执行**的兑换数据库函数。函数一次事务完成兑换和权益更新。前端不接触 service_role。

```text
redeemMembership(rawCode, requestId):
  从受验证的 JWT 取 userId，不信任请求体的 userId/role/days
  校验是可用学生账号，检查限流与码格式
  hash = SHA256(normalize(rawCode))
  数据库事务：
    SELECT code WHERE code_hash = hash FOR UPDATE
    若不存在 → 失败
    若已有兑换记录：同用户 → 返回原结果；其他用户 → 失败
    检查 revoked_at、redeem_before、产品、duration_days
    INSERT entitlement(user, product) ON CONFLICT DO NOTHING
    SELECT entitlement FOR UPDATE
    expires = greatest(server_now, old_expires) + duration_days
    INSERT redemption(code_id UNIQUE, user, expires)
    UPDATE entitlement SET expires_at = expires
    INSERT audit(不记录原码)
  commit 后返回权益
```

顺序先锁码再锁权益，各业务统一锁顺序。同一用户同时兑换不同码也要锁权益行，避免丢失续费；遇死锁/序列化失败有限重试。任何一步失败全部回滚。新码可恢复到期/被撤销权益的规则需在正式产品规则中明确；默认被封禁账户不得兑换。

- 学生仅 SELECT 本人权益；不得 INSERT/UPDATE 自身权益或角色。RLS 加 grants 双重约束。
- 私有码表不暴露 Data API；SQL `security definer` 仅在必要时使用，固定空 `search_path` 并全限定表名，撤销 PUBLIC/anon/authenticated 的内部函数执行权限。
- 管理员页面隐藏不是安全隔离：发码、查用户、撤销码、导出都要在服务端验证管理员。
- 静态网站里预置的完整 VIP 视频/答案，一旦公开 URL 就谈不上真正保护。受限内容需由服务端验证权益后给短时签名地址，不能只拦按钮。
- 管理员端独立构建、独立部署/域名、独立会话键。学生产物不包含管理页面与管理脚本，但依旧必须落实服务端权限。

验收：匿名及普通学生发码请求被拒；前端改日期/改 localStorage 不开通；20 个并发兑换请求同一码仅一条成功记录；同用户两枚不同码正确累加；失败事务无半条权益；刷新、跨设备、登出切换账号结果一致。

## 4. 退出播放页必须立即安静

### 4.1 根因与额外风险

- `assets/js/app.js:100` `routeNow()` 先改 `State.route` 再切换 `.page.active`，无暂停。
- 约 239 行登出无暂停；约 535 行 `pagehide` 只停录音流和保存进度。
- 约 392 行 `closeDict()` 可能再次 `video.play()`：即使补一次 pause，旧回调仍能把视频叫醒。
- 保存前已更改 route/videoId，会把旧视频进度记到新视频；旧账号未完成的网络响应也可能覆盖新账号 UI。

### 4.2 统一 MediaSessionController

管理视频、词典音频、TTS、原句播放、录音回放、录音 tracks、循环定时器、异步任务；每次进入新学习会话分配 `generation`，旧回调必须失效。

```js
// 接口草案：先在旧状态中采样，再释放媒体，最后改路由。
async function navigate(nextRoute) {
  const snapshot = playback.capture(); // userId, videoId, position, watchedRanges
  playback.dispose('route-change');   // 同步暂停并使旧 generation 失效
  progressQueue.enqueue(snapshot);    // 本地落盘，云同步失败稍后重试
  State.route = nextRoute;
  renderRoute(nextRoute);
}

function dispose(reason) {
  generation += 1;
  abortController.abort();
  video.pause();
  wordAudio.pause();
  recordingAudio.pause();
  speechSynthesis?.cancel();
  resumeAfterDict = false;
  clearAllMediaTimers();
  stopRecorderAndTracks();
  releaseOwnedBlobURLs();
}

// 每一次自动恢复播放，必须先检查会话仍属于原用户与原视频。
function mayResume(ticket) {
  return ticket === generation && isCurrentVideoRoute() &&
    !document.hidden && isStudentSessionValid();
}
```

上述函数是接口示意，变量不是现有项目可直接运行的完整实现。特别注意 `play()` Promise、`getUserMedia()` 晚返回、`loadedmetadata`、字典关闭、TTS onend、录音 onstop：都要验证 generation。迟到的麦克风流立即停止所有 tracks；不允许旧回调修改新媒体。

停止时机：路由离开/换视频、浏览器后退、退出登录、账号切换、弹出学习完成面板、`visibilitychange(hidden)`、`pagehide`。返回前台或返回页面默认保持暂停，由用户再次点击播放。

若未来支持“后台听力”，必须显式开关、显式媒体会话提示；也只针对后台切标签，不允许退出视频路由后继续播放。第三方嵌入播放器使用官方 player API 的 pause/destroy，跨域 iframe 不能假定 `.pause()` 可用。

### 4.3 进度和完成弹窗一起修正

当前 `showLessonComplete()` 使用 `Math.max(90, percent || 100)`，即使记录不足也可能显示至少90%。应移除虚假兜底：

- `position_seconds` = 上次位置；`watched_ranges` = 真实播放区间；`active_seconds` = 前台有效观看墙钟时长。三者分开。
- 覆盖率 = 合并已观看区间长度 / 总时长，拖动进度不增加覆盖；倍速区分媒体秒与真实学习秒。
- 课程完成条件由课程定义：覆盖率阈值＋必要任务，不把跳到结尾当掌握。
- “本次收藏” = 会话中新增收藏，而不是整个视频历史收藏。
- 0 收藏时显示“这次没有收藏表达”，隐藏/弱化复习按钮，主操作为“继续学习”；回首页马上停止一切声音。
- 数据同步使用 user_id＋session_id＋event_id 去重；断网重试不双计时。浏览器关闭时网络落库是尽力而为，不能仅靠 pagehide 异步请求保证成功。

| 职场与职业 | 面试、邮件、会议、演讲；IT/金融/外贸/医疗等 | 任务型表达、专业词义、语用、行业场景 | 职业场景与内容许可 |
| 日常生活 | 旅行、社交、海外生活、影视/兴趣 | 高频口语块、交互、听辨与表达 | 场景版本、兴趣标签 |
| 用户自定义 | 自建词表、课程、复习项目 | CSV/词表导入＋同一复习引擎 | 导入来源/版本/授权 |

“所有”不表示世界上每个考试已拥有完整词表。未知考试可通过注册一个版本化目标接入，而不是写死大量 `if (exam === ...)`。正式发布每条路线前，由教研审核官方规格与来源许可。

未成年人路线需年龄适配、监护人及录音隐私方案；成人 Vlog 不应直接推荐给儿童。职业医疗等内容是语言学习材料，不作专业决策指导。

### 5.2 四六级、雅思和托福的已核实区别

- CET4 官方页面：写作15%、听力35%、阅读35%、翻译15%；听力含短篇新闻、长对话、篇章；笔试125分钟。
- CET6 官方页面：同样四类分值，但听力包括长对话、听力篇章、讲话/报道/讲座；笔试130分钟。口试另有考试规格。
- NEEA 当前大纲页面列有《全国大学英语四、六级考试大纲（2016年修订版）》。页面旧发布日期不等于失效；发布时仍要确认有无更新，不能自编“2026新大纲”。
- ETS 当前 TOEFL 内容页列出新版：Reading 的 Complete the Words / Read in Daily Life / Read an Academic Passage；Listening 的响应、对话、通知、学术讲话；Writing 的 Build a Sentence / Write an Email / Academic Discussion；Speaking 的 Listen and Repeat / Take an Interview。评分为1–6，2026年后两年过渡期另有可比0–120总分。题型和分数量表必须版本化。
- 雅思 Academic 与 General Training 应分开；Vlog 可补口语/听辨和话题词，不替代完整的考试阅读、写作、计时模拟。本轮 IELTS 官方页面访问受限，未把未读到的页面内容充当已核实引用；正式路线需补官方题型/评分表核验。

### 5.3 词库：共同底座＋路线映射

```text
语言条目 lexeme（word / phrase / collocation / pattern）
  └─ senses：词性、不同词义、释义、用法、能力等级
      ├─ pronunciations：音标、口音、音源、许可、读法
      ├─ examples：例句、字幕、音视频时间段
      ├─ syllabus_items：属于哪些目标/版本、优先级、证据
      └─ user_item_skills：每个人在认义/听辨/拼写/输出上的状态
```

例如 `bank` 的金融义和河岸义不能只是一张总卡片；`take part in`、`in terms of`、`reach a consensus` 是不同类型的学习条目。词形归一后还要保留原文形态；多词表达不能按空格拆掉再丢失整体意思。

同一个人从四级切到六级，共享已学词义状态，但新增词义、搭配和输出要求仍需学习。不同人各自一份状态，不能读共享 localStorage 的“已掌握”。

词表分四层：

1. 官方大纲明确要求的条目（若确有官方词表）：记录版本和出处。
2. 获许可的真题/语料统计扩展：标记频率、领域，不写成“官方必考”。
3. 目标任务表达：写作论证、邮件礼貌表达、翻译搭配、学术衔接等。
4. 用户个人薄弱项、视频遇词、主动收藏。

每条记录保留 `source_url`、`source_version`、`license_id`、`reviewer`、`reviewed_at`。公开可阅读不等于可批量抓取、复制定义、音频或商业分发。AWL 是学术词表参考，不是托福/雅思“全部必考词”。没有可信的封闭词表能保证覆盖所有未来试题。

### 5.4 计划生成与日常学习闭环

首次设置：主目标、目标版本、当前水平、目标分数、考试日期（可空）、每天时间、薄弱技能、兴趣、英/美音偏好。只保留一个主目标，可有副场景；不要给忙碌用户同时叠五份计划。

诊断：10–15分钟低负担筛查，分别测认义、听辨、阅读和输出；有条件再做专项。结果显示估计与置信度，不把简短测试包装成正式考试分数。无诊断则给保守起点，可随时调整。

每天任务顺序：

```text
到期复习 → 针对薄弱项的短任务 → 匹配语境视频
        → 本日新词义/搭配 → 主动回忆与输出 → 汇总与下次安排
```

- 看视频前给 3–5 个目标表达；先听/看、按需查词、再跟读/复述，不满屏标生词。
- 模式区分“泛听”“精学”“考试专项”，避免考试用户只有看视频入口。
- 每日10/20/40分钟分别生成可完成任务，不要求固定一天背50个。
- 复习超预算时减少或暂停新词；提供最小可完成版本和积压说明，不无限堆待办。
- 漏学后重新分配剩余计划，不把全部漏学任务直接挤到今天。
- 考试期限不足时显示现实的重点覆盖范围和预计缺口，不承诺必达分。
- 每周用真实答题与复习数据调整，用户可以撤销/选择偏好；自动调整保留版本与解释。

### 5.5 推荐算法草案（规则优先，MVP 不依赖昂贵 AI）

先做硬过滤：内容已发布、许可可用、年龄适配、权益可用、目标版本相符、有真实媒体/字幕、未失效。再评分。

```text
priority(item) =
  0.30 × target_importance
  + 0.25 × weakness
  + 0.20 × forgetting_risk
  + 0.15 × available_context_quality
  + 0.10 × interest_fit

所有分量归一到0–1；以上权重是初始产品假设，不是研究结论。
eligible = hardFilter(candidates)
due = sortDueByRiskAndDeadline(eligible)
budget = daily_minutes × 60
先排到期任务，再保留目标所需的最小技能训练，最后排新内容
任务加入前验证 estimated_seconds ≤ remaining_budget
排程用稳定次排序，记录算法版本；剩余时间不足就停止，不硬塞
```

视频匹配：优先覆盖本周目标词义且难度合适的短片；字幕命中必须能定位到具体句和时间；同义词/多义词映射需审核，不能看到字符串就算覆盖。冷启动先按目标、级别、时长人工精选；数据够用后才优化权重。

## 6. 复习引擎与开源代码参考

本轮实际读取 `open-spaced-repetition/ts-fsrs` README、包版本/许可、`fsrs.ts` 与 `algorithm.ts` 的关键实现。

- 审阅提交：`c8ca282edc3fe1cdfa1c24912437938b63a25cb3`。
- 该提交 `packages/fsrs/package.json`：版本 **5.4.2**，Node >=20。
- 包许可证：MIT；分发需保留版权和许可证。这不授权复制其他产品的词库、定义、音频。
- 核心记忆状态是 Difficulty、Stability、Retrievability；结合复习时间和 Again/Hard/Good/Easy 反馈，产生下次到期时间及日志。
- `algorithm.ts` 包含 forgetting_curve、next_interval、next_difficulty、next_recall_stability；`fsrs.ts` 提供 repeat、next、get_retrievability 等接口。

接入示意，需固定依赖并写服务端测试后上线：

```ts
import { fsrs, createEmptyCard, Rating } from 'ts-fsrs';
const scheduler = fsrs({ request_retention: 0.9 });
const oldCard = storedCard ?? createEmptyCard(serverNow);
const result = scheduler.next(oldCard, serverNow, Rating.Good);
// 在同一事务中保存 result.card 和 result.log，按 event_id 去重。
// card 必须来自当前用户、当前词义、当前练习维度；不接受客户端传完整掌握状态。
```

0.9 是建议起点，不是合格率保证。认义、听辨、拼写、主动输出分别记忆建模；看过字幕不自动记 Good。不会答应选 Again，答出但费劲才是 Hard；不要将 Hard 当错误按钮。保留原始日志和算法版本，升级模型能回放重算。数据少时用默认参数，不做看似精确的个人参数拟合。

商业应用可观察公开功能，但未取得其闭源代码。本文学习计划、VIP、播放生命周期的代码是为 Eastudy 拟议的实现，而非声称复制某个商业产品后台。

## 7. 发音系统：从零散 TTS 到完整音频链路

### 7.1 当前状态与用户反馈

源码 `assets/js/app.js:448` `speechWord()` 调用浏览器 `speechSynthesis`，固定 `en-GB`；约 490 行还有按钮调用。这不等于用户可正常使用的发音系统：缺少词库音源、英美音选择、加载/失败状态、统一互斥和设备适配验证。用户反馈“没有发音”仍需在当前页面复现，不应仅看到函数就判定没问题。

### 7.2 学生侧交互

- 单词卡/字幕词典/短语卡/复习卡都有清晰发音按钮，旁边显示 IPA 和英/美音；与朗读整句按钮区分。
- 支持正常/慢速，默认正常；慢速适度（如0.8倍），不把变形音频当标准发音。
- 短语整体播放；视频原声按钮跳到真实字幕片段，不用孤立逐词 TTS 拼句。
- 状态：空闲→加载→播放→结束；失败显示可重试提示。不无声失败、不死转圈。
- 连点只播放最后一次；新音频开始前停止旧音频/TTS。词典发音默认暂停视频；同会话关闭词典是否恢复按产品规则，但离页绝不恢复。
- 英美音偏好可存个人设置；实际设备没有目标口音时标“系统近似音色”，不冒充真人英音/美音。

### 7.3 音源优先级和数据模型

优先级：**有许可的高质量词典/录制音频 → 获许可并缓存的云端 TTS → 浏览器 TTS 兜底 → 明确提示暂缺**。

Vlog 原声是独立的语境来源，不能当作任意单词独立发音的许可证。

```text
pronunciations:
  id, lexeme_id / sense_id, dialect(en-GB/en-US), ipa,
  audio_asset_id, source_type(recorded/cloud_tts),
  voice_id, provider, content_hash, license_id,
  duration_ms, status, reviewed_at

audio_assets:
  id, storage_key, mime_type, size_bytes, checksum,
  source_url, attribution, license_id, usage_scope
```

缓存键应包含 text_normalized＋语言口音＋voice_id＋语速＋provider_version，不只按单词字符串；多音词依据词性/词义选音。缓存不含用户私人文本或录音，避免多人串流。

### 7.4 浏览器 TTS 兜底示意

```js
function chooseVoice(voices, locale) {
  return voices.find(v => v.lang.toLowerCase() === locale.toLowerCase())
    ?? voices.find(v => /^en(?:-|$)/i.test(v.lang))
    ?? null;
}
// 初始化时读取 getVoices；若为空，监听 voiceschanged 再更新可选音色。
// 必须由用户点击触发，speechSynthesis.cancel() 后再 speak()。
// utterance.lang / voice / rate 显式设置，处理 onstart / onend / onerror。
// generation 校验所有回调；离页 speechSynthesis.cancel()。
```

系统 TTS 音色依赖设备，有些由远程服务提供；不能承诺完全离线或无网络传输。Safari/iOS、Android Chrome、Windows Chrome 要分别验证首次点击、锁屏、电话打断、蓝牙耳机、静音、弱网与音色延迟加载。

### 7.5 跟读与评分

MVP：听原声→录音→停录→回放对比；录音默认仅本机当前会话，不自动上传。只有用户明确选择云同步/评分才上传，并说明供应商、用途、保留期和删除方式。切换账号/离页停止麦克风；blob URL 及时释放。

HTTPS/localhost 可用性、权限拒绝、没有设备、录制格式、麦克风被占用都有降级提示。不请求摄像头。录音最长时间限制，避免意外持续采集。

后续自动评分：选择专门发音评估服务，区分准确性/流利度/韵律/完整度，提供不确定性和反馈；普通语音转文字不是音素评分。自动反馈不等于雅思/托福官方口语成绩；不要用装饰性的随机分数。上线前用不同口音、性别、设备、噪声样本校准误差。

## 8. 首页和学习页如何承载这些能力

首页主区：

1. “继续我的计划”：目标、版本、每日预算、今日剩余任务、一个开始按钮。
2. “到期复习”：待复习词义/短语/听辨，显示预计分钟。
3. “今天的语境视频”：为什么推荐、覆盖哪些目标表达、是否已解锁。
4. “专项训练”：按路线展示四级听力/翻译，或托福新版口语等，不显示无内容的空入口。
5. “发现”：保留自由探索 Vlog，不强迫所有人走考试计划。

学习页：视频＋可定位字幕＋词义卡＋英美发音＋原句回放＋收藏/加入计划；完成后显示真实观看和任务结果。移动端用视频/字幕/任务切换，不让所有面板挤一屏。

账户面板：数据库昵称、普通/VIP、真实到期、激活码兑换、主目标、设置。学生端不出现管理员链接。管理员端：内容审核、目标版本、词表许可、音频补缺、激活码批次、脱敏统计。

## 9. 数据库与接口分层

### 9.1 新增逻辑实体（不是一次建完所有表）

| 领域 | 实体 |
|---|---|
| 目标与规格 | learning_tracks、track_versions、skill_blueprints、syllabus_items |
| 内容与语言 | lexemes、senses、expressions、examples、pronunciations、licenses、video_item_links |
| 个人计划 | learner_goals、learning_plans、daily_tasks、diagnostic_attempts |
| 复习 | review_cards（user+sense+dimension唯一）、review_events（event_id去重） |
| 媒体与学习记录 | learning_sessions、playback_checkpoints、watched_ranges |
| 会员 | activation_codes、code_redemptions、membership_entitlements、membership_audit |

已有 profiles/user_vocabulary/user_progress 等表优先做增量兼容或映射，不直接删表重建。旧“mastered”不是新FSRS状态，迁移保留原值并标记待复测，不伪造历史复习日志。

### 9.2 接口契约草案

| 接口 | 关键规则 |
|---|---|
| `GET /me` | JWT对应的个人资料和服务端权益；无密码信息 |
| `POST /membership/redeem` | rawCode、requestId；身份从JWT取；原子兑换 |
| `POST /admin/activation-batches` | 服务端管理员检查；数量、天数、产品白名单 |
| `GET /tracks` | 只返回已发布版本及真实内容覆盖情况 |
| `POST /plans` | goal/version/dailyMinutes；返回计划与不可满足项 |
| `GET /tasks/today` | 用户时区日期；可解释、幂等，不每刷新重排 |
| `POST /reviews` | cardId、grade、eventId、expectedVersion；服务端算调度 |
| `POST /progress/checkpoint` | sessionId、videoId、position/ranges、eventId；所有权校验 |
| `GET /pronunciations/:id` | 许可与权益检查；返回音源信息/短时地址 |

并发：复习卡乐观版本控制；重复eventId返回原结果；冲突刷新重试。服务端不能盲信客户端“已掌握”“已观看999小时”。远程请求完成时再次检查当前用户ID和会话版本，避免A退出、B登录后被A响应覆盖。

RLS：所有私人学习表使用 auth.uid() 与 user_id 对应；学生只写本人普通学习操作。管理员统计与原始私人录音分权限；公开内容、个人记录、管理数据分别授权。列级写权限与 RLS 一起审计，不能让用户更新自己的 role/VIP/认证字段。

## 10. Supabase 免费版的现实实现

- Pages 继续承担静态前端；Supabase Auth/Postgres 承担账号、记录和计划；轻量 Edge Function 承担兑换等受限操作。
- 初期规则推荐＋FSRS，无需每次看词都调用大模型。
- 视频及发音音频不要无限塞数据库；数据库存元数据，媒体放有许可、可控成本的对象存储/CDN。大视频、短信、TTS、自动评分不是因为用免费数据库就免费。
- 学习事件不逐秒写库；合并区间、定期checkpoint、离页本地队列，减少行数和请求；为user_id/due/date建立索引。
- 只存必须数据，制定日志保留期；免费层停用/容量/流量限制按控制台实时配额核对，本稿未核实当前具体配额，不承诺永久免费和无上限。
- 重要schema与内容版本进Git；账号数据、原激活码、录音、service_role不进Git。生产备份和恢复演练要落地，不能把Git当数据库备份。

## 11. 实施顺序和上线闸门

### P0：先修可信度与已有故障

5. 本地测试 → 预览部署 → 用户验证 → 生产发布，记录回滚提交。

### P1：完整基础设施

6. 测试库编写权益迁移、RLS、兑换事务和管理发码；并发、权限、回滚测试通过后生产增量迁移。
7. 上线单词/短语发音按钮、TTS适配、统一音频互斥；接入已确认许可的英美音源；录音本地回放。
