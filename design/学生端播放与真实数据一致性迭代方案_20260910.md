## 3. 成熟项目的可借鉴实现

本次实际读取了以下公开稳定版本源码；不声称拿到了 YouTube、B 站等闭源产品源码，也不把实验 Demo 当成生产证据。

1. **Video.js 8.23.4**：`PosterImage` 监听 posterchange；`LoadingSpinner` 独立组件；Player 单独处理 waiting、canplay、playing。waiting 后用实际时间推进确认已恢复，而不是把任意 timeupdate 都当作播放成功。
   - https://github.com/videojs/video.js/blob/v8.23.4/src/js/poster-image.js
   - https://github.com/videojs/video.js/blob/v8.23.4/src/js/loading-spinner.js
   - https://github.com/videojs/video.js/blob/v8.23.4/src/js/player.js
2. **hls.js 1.6.13**：当前项目使用的正是这个版本。EWMA 估算器根据分片字节数/耗时统计带宽，使用快慢两条滑动估计的较小值，降档快、升档更谨慎；ABR 控制器比较预估下载耗时和缓冲可支撑时间，也考虑播放倍速。
   - https://github.com/video-dev/hls.js/blob/v1.6.13/src/utils/ewma-bandwidth-estimator.ts
   - https://github.com/video-dev/hls.js/blob/v1.6.13/src/controller/abr-controller.ts
3. **Moodle 4.5.0**：课程进度从指定用户的活动完成记录计算 `completed/count`；无可计算数据返回空状态，不硬写一个完成比例。借鉴“当前用户 + 真实成员 + 明确完成条件”，不直接搬用其 GPL 实现到当前项目。
   - https://github.com/moodle/moodle/blob/v4.5.0/completion/classes/progress.php
4. **MDN waiting 事件**：播放因临时缺数据停止会触发 waiting；临时缓冲不是内容删除。
   - https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/waiting_event

适配原则：保留现有原生 JS、hls.js、Supabase、Cloudflare R2；借鉴状态和数据规则，不同时安装第二套播放器，不重写 ABR，不把外部项目源码不加审核整段复制进来。

## 4. 播放、封面、字幕与画质

### 4.1 独立状态，不再一个布尔值管所有东西

```js
// 新增 shared/player-state.js；状态机为本项目设计。
export const initialPlayerState = () => ({
  catalog: 'loading',       // loading | ready | error
  session: 'loading',       // loading | ready | expired | error
  media: 'idle',            // idle | loading | ready | playing | buffering | paused | ended | error
  captions: 'loading',      // loading | ready | empty | error
  firstFramePresented: false,
  playRequested: false,
  error: null,              // { stage, code, retryable, requestId }
});

export function currentCaptionView(status, rows, time) {
  if (status === 'loading') return { kind: 'loading', text: '字幕正在加载中…' };
  if (status === 'error') return { kind: 'error', text: '字幕加载失败，可重试；视频仍可播放' };
  if (status === 'empty') return { kind: 'empty', text: '此视频暂未提供学习字幕' };
  const index = rows.findIndex(s => time >= s.startTime && time < s.endTime);
  if (index < 0) return { kind: 'gap', text: '当前片段暂无对白', index: -1 };
  return { kind: 'cue', sentence: rows[index], index };
}
```

只有权威字幕请求成功且实际为空，才能设置 empty。若目录承诺字幕数量 >0 而载入为空，视为不一致错误，不静默说“没有字幕”。片头可以显示“字幕将随对白出现”，句间停顿安静留空；不能提前播放未来句，也不能把上句一直挂在屏幕上。

### 4.2 初始化门禁与过期请求保护

以下是替换 bootVideo 的编排骨架。`AppReady`、`PlayerUI`、`createSession` 是需要新增的适配器，不是现有库函数。

```js
let activeMount = null;

async function mountVideo(videoId) {
  activeMount?.abort();
  const controller = new AbortController();
  activeMount = controller;
  const valid = () => !controller.signal.aborted && activeMount === controller;
  PlayerUI.reset({ title: '视频正在加载中…', duration: '--:--' });

  try {
    // AppReady.catalog 在登录和权威 published 快照获取成功后才 resolve。
    // 请求失败必须 reject；不能返回空快照冒充“没有内容”。
    const snapshot = await AppReady.catalog();
    if (!valid()) return;
    const item = snapshot.videos.find(v => String(v.id) === String(videoId));
    if (!item || item.status !== 'PUBLISHED' || item.deletedAt) {
      PlayerUI.notAvailable();
      return;
    }
    PlayerUI.showMetadata(item); // duration 来自可信元数据，不用默认 30 秒。
    await AppReady.mediaSession();
    if (!valid()) return;

    const video = document.getElementById('video');
    const cover = item.cover || '';
    if (cover) video.poster = cover;
    else video.removeAttribute('poster');
    PlayerUI.showPoster(cover); // 无封面时中性占位+“封面准备中”，不用演示图片。

    const rows = snapshot.sentences[String(item.id)] || [];
    PlayerUI.setCaptions(rows, rows.length ? 'ready' : 'empty');
    const session = createSession({ video, item, signal: controller.signal });
    controller.signal.addEventListener('abort', () => session.destroy(), { once: true });
    PlayerUI.bindPlay(() => session.requestPlay());
  } catch (error) {
    if (valid()) PlayerUI.showStageError(error); // 有限重试，不误报删除。
  }
}
```

实现要求：

- 先绑定播放器事件，再 attach/load；销毁时解除旧事件、计时器、字幕监听和质量选择器，旧实例的 AbortError 不显示为新视频失败。
- `poster` 不足以稳定跨浏览器保留画面时，加独立封面层；用户点击后开始加载，第一帧真实呈现后移除封面层。暂停后保留当前视频画面，不恢复花朵。
- `requestVideoFrameCallback` 可用时确认首帧，否则使用 playing + HAVE_CURRENT_DATA 作为兼容路径。
- 首次加载：封面 + 加载圈 + “视频正在加载中”；播放中断：保留最后一帧 + “正在缓冲”。超过约 8 秒改“加载较慢，正在尝试恢复”，不是直接宣判资源不存在。
- 不编造剩余秒数。没有足够分片测速样本时只显示阶段；可显示已加载的缓冲条。
- 手动暂停后不会因迟到的 canplay 自动播放；恢复源时仅在用户仍希望播放时继续。
- `play()` 被浏览器拒绝时显示“请点击播放”，不是“视频不存在”。
- 元数据无效时禁用拖动，时长显示 `--:--`；响应到达后显示 19:26 / 10:43 等真实值。
- 进入新页面后检查 route + mediaVersion + generation；云端更新只改标签/名称时不重启正在播放的视频。字幕版本变则重绘字幕，媒体版本变则显式换源。

### 4.3 媒体鉴权和错误恢复

错误输出统一为 `{stage, code, retryable, requestId}`，日志不得包含 Token、Cookie、签名 URL 查询值。

| 错误 | 学生文案 | 自动行为 |
|---|---|---|
| 内容目录获取超时 | 内容加载较慢，点击重试 | 有限退避重试目录，不显示视频已删除 |
| 401/会话过期 | 正在恢复登录状态 | 同一鉴权故障只续期一次；重建 /api/session，再重试原媒体请求 |
| 403/权限不足 | 当前账号暂无观看权限 | 不无限刷新登录，不静默公开媒体 |
| 已授权但对象/映射不存在 | 视频资源暂不可用，请联系管理员 | 记录缺失的是 manifest/variant/segment/cover；保留目录与字幕 |
| 网络超时/5xx | 加载较慢，正在重试 | 使用播放器内置请求重试预算；耗尽后提供手动重试 |
| 解码失败 | 当前画质播放异常 | 受限 media recovery；必要时切兼容源，明确提示 |
| 字幕请求失败 | 字幕加载失败，点击重试 | 不挡住视频播放 |

`/api/session` 必须与 Supabase TOKEN_REFRESHED 对接，在旧 Cookie 过期前刷新；处理学生/管理员同时打开时的会话归属，不让不同账号互相覆盖一枚未分 scope 的 Cookie。每次切账号清理对应媒体会话；Cookie 不落日志。

媒体请求端不要把所有 RPC 错误都变成 502。保留鉴权失败、映射不存在、R2 不存在、依赖故障的机器码与 requestId；向用户不暴露对象存储内部密钥。

首轮不放宽权限、不把私有媒体改公共。每分片鉴权的优化需先测 TTFB、RPC 耗时与 R2 耗时；若确是瓶颈，再评审短时授权票据和缓存键隔离。不能为提速跨用户缓存授权结果。

### 4.4 真正的自动画质

当前两条视频在目录中已有 480p/720p 两档。当前 hls.js 的 `currentLevel = -1` 已经表示自动 ABR，因此不是“完全没有自动算法”；但实际清单、分片和降档行为尚需播放验证。

```js
// shared/media-player.js 中显式区分资源类型。
function mediaKind(item) {
  if (item.playback?.masterUrl) return 'hls';
  const path = new URL(item.mediaUrl, location.origin).pathname;
  if (/\.m3u8$/i.test(path)) return 'hls';
  return 'file'; // 旧数据兼容；新数据增加明确 container/mime 字段。
}

// HLS 生命周期内，事件监听必须先于 loadSource / attachMedia。
const hls = new Hls({
  startLevel: -1,
  capLevelToPlayerSize: true,
  maxBufferLength: 30,
  autoStartLoad: false, // manifest 可先读取，分片在用户点击后加载。
});
let selectedMode = 'auto';
function chooseQuality(value) {
  selectedMode = value;
  if (value === 'auto') hls.currentLevel = -1;
  else hls.currentLevel = Number(value); // 先验证为当前 manifest 有效 level。
}
hls.on(Hls.Events.LEVEL_SWITCHED, (_event, data) => {
  const level = hls.levels[data.level];
  qualityStatus.textContent = selectedMode === 'auto'
    ? `自动画质${level?.height ? ` · 当前 ${level.height}P` : ''}`
    : `${level?.height || ''}P`;
});
```

上述是 HLS 分支核心，不是完整播放器：还需 mount/destroy、单一 retry budget、恢复位置、requestPlay/startLoad、错误分类和 native 分支。

- hls.js 不可用且浏览器 `canPlayType('application/vnd.apple.mpegurl')` 可播放时使用原生 HLS。原生 HLS 的自动档由浏览器控制，若无档位 API 则显示“自动画质 · 浏览器控制”，不猜当前 720P。

- 自动档不包含未切片的 1080P 原画；原画是显式手动选项。保持学习位置、倍速、静音状态及用户播放意图。
- 不用 navigator.connection 单独决定画质；可以作为初始提示，最终依赖 hls.js 的下载耗时和缓冲反馈。
- 卡顿恢复归一个控制器处理，不能应用层和播放器层各自无限重试。
- 测试使用真实带宽限制让 720→480 降档，再恢复网络观察稳定升档；记录 level、bufferSeconds、bandwidthEstimate、stallCount。
- 当前不新增多余的转码档。极差网络不足以支撑 480p 时，明确提示切音频/暂停等待的可用性；是否增设 360p 单独核算存储后再决定，不悄悄增加体积。

```js
function patchById(rows, id, patch) {
  let found = false;
  const next = rows.map(row => {
    if (String(row.id) !== String(id)) return row;
    found = true;
    const provided = Object.fromEntries(
      Object.entries(patch).filter(([key, value]) => key !== 'id' && value !== undefined)
    );
    return { ...row, ...provided, id: row.id };
  });
  if (!found) throw new Error('ENTITY_NOT_FOUND');
  return next;
}
```

```js
const LEVEL_ZH = {

function difficultyLabel(level) {
```

### 7.2 统一计量定义

| 指标 | 定义 |
|---|---|
| 有效学习时长 | 用户确实播放/参与学习的现实时间，不是拖动后位置，也不是观看媒体秒数 |
| 覆盖进度 | 同一媒体版本中真正播放过的时间区间并集 / 媒体总时长 |
| 已学习视频 | 存在有效学习记录的视频数；列表再分“学习中”“已完成” |

### 7.3 播放计时采样与持久重试

计时由独立 tracker 维护，不再在巨大 timeupdate 回调里直接加累计数。

```js
// 判断相邻采样是否可计入；采样时间使用 performance.now()。
function activeSlice(previous, current) {
  const wall = (current.monotonicMs - previous.monotonicMs) / 1000;
  const media = current.mediaTime - previous.mediaTime;
  if (!previous.running || !current.running || !current.visible || !previous.visible) return null;
  if (previous.seeking || current.seeking || wall <= 0 || wall > 3 || media <= 0) return null;
  const expected = wall * previous.rate;
  if (Math.abs(media - expected) > Math.max(0.75, expected * 0.35)) return null;
  return { activeSeconds: wall, watchRange: [previous.mediaTime, current.mediaTime] };
}
```

playing 启动；waiting/stalled/pause/seeking/ended/hidden/换页先结算有效末段后停止；seeked/速率变化重置基线，不把跨事件大间隔归入学时。首帧未到、视频未推进不计时。阈值为首版采样策略，需在不同浏览器验证，不能宣称能证明人眼一直注视屏幕。

### 7.4 服务端事件、并发与历史兼容

建议 v3 不破坏 v2 的旧客户端，部署过渡期分别识别两种事件，最终汇总使用同一可信账本。

事务顺序必须固定：

```text
auth.uid() → 严格校验 → 每用户事务锁 → eventId 幂等检查
→ 写事件/有效时间段 → 合并该媒体版本覆盖
→ 更新同用户位置版本 → 重算受影响日期 → 返回确认汇总
```

```sql
-- v3 RPC 事务内部骨架，不是完整可直接部署函数。
perform pg_advisory_xact_lock(hashtextextended(auth.uid()::text, 0));
-- event_id 与 user_id 建唯一键；唯一键冲突只返回原回执。
-- 不接受客户端指定写入 user_id，一律 auth.uid()。
-- 日汇总取时间区间的并集，不累计重试次数。
select coalesce(sum(extract(epoch from upper(r)-lower(r))), 0)
from (
  select unnest(range_agg(active_range * tstzrange(v_day_start,v_day_end,'[)'))) r
  from public.study_activity_intervals
  where user_id=auth.uid()
    and active_range && tstzrange(v_day_start,v_day_end,'[)')
) merged;
```

具体落地要求：

1. user_id、session_id、eventId、序号、时长、时间戳必填；显式拒绝 NULL/NaN/Infinity、未来异常值、非法视频/无观看权限、伪造 mediaVersion、超限 ranges。
2. 媒体版本和总时长从服务端已发布输出校验。客户端不能通过缩短 duration 伪造完成；字幕修订不改变媒体版本。
3. 只记录真正活动的短区间，客户端不得把暂停前后累计秒数倒推成一个连续区间。请求报告 activeSeconds 要与活动区间总长度一致。
4. 同账号同时手机和电脑观看，累计墙钟时间按重叠区间并集计算，不翻倍。同一视频覆盖用媒体时间区间并集。
5. 若明细按视频可加总，另记录 creditedRanges：在每用户锁内，将新活动区间减去已记账区间，先确认的事件获得重叠时长归属；后确认事件仍可更新各自覆盖，但不重复增加学习时长。使用独立 v3 记账结构，不能将多段并集塞进现有单段主键行。明确区分“播放覆盖”与“已计入学时”。
6. 首次位置不能拿客户端旧时间与新行默认 now() 比大小后跳过。首次直接接纳合法位置；同会话后续按 seq；跨会话使用 baseRevision 冲突检测。旧离线事件可合并覆盖/时长，但不得把较新续播位置回滚。
7. 换媒体版本分别保留历史，当前版覆盖从当前版事件算；不沿用旧 completed_at 或旧 max(duration)。
8. v2 前的日统计需保存 legacy baseline 与切换时点。不能一写新事件就用新账本合计覆盖掉当日已有历史秒数；无法恢复细粒度的旧记录在明细标“历史汇总”，不捏造逐视频分配。
9. 账号时区从云端学习档案读取并验证，前端显示使用同一时区。跨午夜事件分日；日期请求分页，终身汇总不截断到 366 天。
10. 离线事件允许窗口和未来偏差由服务器限制并写入契约；超过窗口保留“未接纳”说明，不静默丢弃，不承诺任意久离线必然接纳。
11. v2/v3 并行期的去重与 legacy 边界先用数据库集成测试验证，禁止单纯复制一份函数后两边同时累计。

```js
function parseHashRoute(hash) {
```
